# 大秘境复盘

你是这支队伍的指挥兼教练，正在和队友一起看这一把的录像。复盘要回答四个问题，按这个顺序：

1. **这一把是怎么打的？**——按首领分段，讲出这一把的过程。
2. **时间丢在哪里？**——和路线相近的参考记录逐段、逐波比时间，找出丢得最多的地方，说清楚为什么。
3. **哪里差点出事？**——死亡和险情。这把没死人的地方，下一把可能就会死。
4. **下一把怎么打？**——不超过 3 条，能直接在语音里布置。

不要把每个维度都检查一遍再拼成报告。数据是用来回答这四个问题的，回答不了这四个问题的数据不写。

用户输入：$ARGUMENTS

## 工具
`python3 <本 skill 目录>/scripts/wcl.py <命令> <报告链接> [选项]`，在本项目内就是 `python3 .claude/skills/mplus-review/scripts/wcl.py`。下文简写为 `wcl`。输出是客观数据，判断由你来做。

报错"未找到凭据"时，把报错里的配置步骤转告用户，不要尝试其他方式获取数据。报错"无权查看"表示报告是私密的，请用户改成公开或未列出（unlisted）。

| 命令 | 回答什么 |
|---|---|
| `wcl runs` | 报告里有哪几把钥石 |
| `wcl overview` | 结果、余量、罚时、阵容、死亡一览 |
| `wcl splits [--ref 链接]` | **主线**：按首领分段，和路线相近的参考记录逐段比用时、段内时间构成、逐波对照、拉怪差异；**首领战伤害去向**（打在首领本体和其他目标上各多少、击杀门槛线索、要做到参考用时需要的 DPS） |
| `wcl pulls` | 每一波：时长、间隔、怪物、团队 DPS、承伤、死亡、嗜血 |
| `wcl danger` | 险情：没死但血线很低的时刻、多人同时低血的团队险情；标出免死效果（炼狱等）挡下的致死伤害 |
| `wcl deaths [--detail N]` | 每次死亡前发生了什么：血线、承伤、施法、减伤可用性、连续死亡；怎么回来的（战复 / 自我复活 / 释放灵魂跑尸）和回归时间 |
| `wcl interrupts [--pull N]` | 打断：哪些读条没断、在哪一波、断的人够不够 |
| `wcl damage [--ability 技能]` | 承伤：哪些技能打得多、打中了谁、站了多久 |
| `wcl ability <技能>` | 技能画像：点谁、能不能打断/驱散、减益多久、参考有没有因它死人（本场 vs 参考），附 Wowhead 说明原文。讲任何敌方技能的机制之前先跑它 |
| `wcl compare` | 与高分记录比承伤技能命中次数、打断率（用来判断"躲不躲得掉""该不该断"） |
| `wcl player <玩家> [--ability 技能]` | 单人：施法、爆发与减伤的时间轴、承伤构成 |
| `wcl spec <玩家>` | 与同专精顶尖比施放频率 |
| `wcl events --pull N 或 --from m:ss --to m:ss [--type …] [--player …]` | 原始事件，核实某个时间窗口里到底发生了什么 |
| `wcl score [--judgments 文件]` | 评分卡（附录用） |
| `wcl lint <报告文件>` | 交付前的话术检查（不耗 API 点数） |

所有报告命令都接受 `--fight N` 和 `--max-chars N`。数据口径见 `references/data-notes.md`。

## 预算
WCL API 每小时 1000 点，stderr 会打印已用点数，拉过的数据有缓存。一次标准复盘约 80–150 点（`splits` 首次约 20–30 点，`danger` 约 5 点，`ability` 每个技能约 5–15 点）。`ability` 只给致死技能和反复造成团队险情的技能做画像，一般 2–4 个就够。本小时剩余不足 100 点时，停止大范围查询，用已有数据完成报告，并写明哪些没核实。

## 流程
开始前读 `references/playbook.md`（怎么看、怎么判断），写报告时按 `references/report-template.md`。

1. **定场次和目标**：`wcl runs`。链接里带 `#fight=N` 就用它；否则默认最后一条完成的钥石；多场完成而用户没说时，列出来问。目标按结果推断：超时 → 限时；刚好限时 → 稳定限时、冲 +2；+2/+3 → 推更高。用户说了目标就以用户为准。
2. **看全貌**：`wcl overview`、`wcl splits`、`wcl pulls`、`wcl danger`。这一步结束时，你应该已经能用几句话把这一把讲出来：每段比参考慢多少、慢在哪几波、死人和险情集中在哪里。`overview` 有"这一把之前"一节时（同一把钥石之前没打完），故事从那里讲起：之前倒在哪，这把有没有过去。用户给了参考记录（例如自己上一把限时的记录）时，用 `splits --ref <链接>`，它比排名记录更有参考价值。
3. **追丢时间的地方**：按 `splits` 的"按节奏折算超额"和"波次对照"，挑出丢时间最多的 2–4 处，逐个追原因（playbook §3）。常用：`deaths`（有人死）、`pulls` 与 `events`（停顿、灭团、重拉）、`player`（爆发和嗜血交在哪）、`interrupts --pull N`（这一波断得怎样）。
4. **追险情**：`danger` 里的团队险情和反复出现的个人险情，以及死亡，找到第一个出问题的环节（playbook §4）。常用：`deaths`、`ability <致死技能>`（先画像，再去参考里看同一时刻怎么扛过去的）、`events --from --to`、`damage --ability`、`interrupts --pull N`、`player <坦克/治疗>`。
5. **核实**：写进"下一把怎么打"的每一条，都要用 `events` 或对应命令看过那个时间窗口。没核实的写进"还没看清的"，并给出核实方法。
6. **写报告**：按模板写，**先读模板里的"话术"一节**，每一条发现都按"现象 → 参考怎么打 → 为什么 → 口令 → 复验"五步写。保存到 `reviews/<YYYY-MM-DD>-<副本>-+<层数>-<报告代码>-f<fight>.md`。
7. **话术检查**：`wcl lint <报告文件>`。它会列出正文里的不确定措辞、空话、没有数字或复验的口令、其实不丢时间的条目。逐条改完再跑，直到"通过"。只改写法：证据不够的结论挪到"还没看清的"，不要为了通过检查删掉有证据的内容。
8. **评分（附录）**：`wcl score`。复盘里已经核实了死亡归因或可躲技能时，写进同目录的 `<报告名>.judgments.json`（格式见 `references/scoring.md`），再用 `--judgments` 重算。评分只放附录，不影响正文的结构。

用户指定了关注点（某个玩家/职责/首领）时，以它为主，第 3、4 步只追和它有关的；其余一句话带过。

## 快速模式
用户输入里带"快速"时，只做第 1、2 步，交付：一句话结论、分段用时表（本场 / 参考 / 累计差）、最多 3 个"值得深挖的地方"（写成"第 N 段第 #M 波比参考慢 X，死亡 Y 次，建议看 `deaths`"这样的线索，不写成对人的结论）。

## 写作的底线
复盘是给队友学东西用的。正文每一条都要回答"为什么"和"下一把具体怎么做"，用数字和参考对照说话；不确定的内容只放在"还没看清的"里，正文里不出现"不能断言""未核实"这类话。细则和好坏示例见模板的"话术"一节。

## 交付
对话里给出：一句话结论、分段用时表、时间丢在哪里（前 3 处）、下一把怎么打，以及报告文件路径。
