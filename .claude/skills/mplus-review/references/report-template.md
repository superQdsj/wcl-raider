# 复盘报告模板

报告是给队友看的，读起来应该像赛后复盘，而不是体检报告。篇幅控制在一两屏：正文只写四个问题的答案，数据说明和评分放到附录。

```markdown
# {副本} +{层数} 复盘 —— {结果}（{官方用时} / {限时}）

> 报告：{链接} · {日期} · 阵容：{坦克} / {治疗} / {输出×3}
> 参考：{参考记录：层数、用时、装等；为什么选它们，例如"路线相似度 90% 左右的同层记录"或"你们上周限时的那一把"}

## 一句话
{这一把输在/赢在哪里，带上最关键的数字。例如（虚构）："超时 40 秒。前两个首领基本跟上参考的节奏，差距几乎都出在第 3 段：姆沁巴开怪 21 秒团灭，重打加重拉多花了约 2:20。"}

## 这一把是怎么打的
| 段 | 本场 | 参考 | 本段差 | 扣掉整体快慢后 | 到这里累计 |
|---|---|---|---|---|---|
| 1. 开场 → {首领1} | … | … | … | … | … |

{如果 `overview` 有"这一把之前"（同一把钥石之前没打完），先用一两句话交代：之前打了几次、都倒在哪里、这一把怎么过去的。}

{每段两三句话：用时和参考比怎样，这一段里最重要的事（哪一波特别长、谁死了、灭团或重拉、嗜血开在哪），拉怪和参考有什么不同。没什么问题的段一句话带过。}

## 时间丢在哪里
按丢的时间从多到少，通常 2–4 处：

1. **{位置：第 N 段 #M 波 / 首领}：多花约 {X}**
   {发生了什么，为什么会这样（证据：时间点、数字、和参考的对比），代价是多少。}
2. …

{整体输出差距（各段都慢一点、超额不大）写成一句话放在最后，不要拆成好几条。}

## 差点出事的地方
{团队险情、反复出现的个人险情、死亡（每串连续死亡写一次，指出第一张倒下的骨牌）。重点讲下一把还会遇到的危险：哪一波、什么技能、谁、为什么没撑住或者差点没撑住。}

| 时间 / 波 | 发生了什么 | 起因 | 下一把怎么防 |
|---|---|---|---|

## 下一把怎么打
最多 3 条，能直接在语音里布置：

1. **{一句口令，例如"姆沁巴开怪前确认团减转好，第一次 X 读条时交"}**（负责：{谁}）
   为什么：{这把在这里丢了多少时间 / 差点出了什么事}。复验：{下一把看什么指标}。
2. …

## 个人
{只写和上面几件事有关的人，每人 2–3 条，先说做得好的。没有深挖的人不写。}

## 还没看清的
{证据不够、没有核实的疑点，每条写明怎么核实（哪条命令、看哪个窗口）。没有就删掉这一节。}

---
## 附录
### 评分
{`wcl score` 的团队和个人评分表；N/A 和"不发布"照实写出原因。}

### 数据说明
{参考记录的可比性（装等、层数、阵容差异）、不可用的指标（样本太小、计数不一致、输出被截断）、没查到的机制。每条一行。}
```

## 话术：写成能教会人的复盘
读报告的是队友。读完他们要知道三件事：**哪里出了问题、为什么、下一把具体怎么做**。只复述"发生了什么"的复盘没有教学价值，等于让队友自己再看一遍日志。

### 每一条发现都按这五步写
1. **现象**（带数字和对照）：在哪、用了多久或掉了多少血，参考是多少。
2. **参考怎么打的**：同一个位置，快的或没出事的记录做了什么不一样的事。
3. **为什么**（机制）：一句话讲清因果，让读的人下次能自己认出同样的情况。
4. **口令**：谁、看到什么信号时、做什么、要做到什么数值。
5. **复验**：下一把看哪个数字，就知道改好了没有。

写不出第 3 步，说明原因还没追到：回去用工具追（playbook §3、§4），追不到就放进"还没看清的"，不要写进正文。

### 规则
- **结论先行。** 每段第一句就是结论，后面才是证据。不要按命令输出的顺序复述数据。
- **数字要带对照。** "3:10"没有意义，"3:10，快的参考 2:15"才有。工具已经算好的推算（例如 `splits` 线索里"要做到参考用时，打首领本体的 DPS 需要约 X"）直接写进口令。
- **用玩家的话讲机制。** 写"她会第二次飞上天，再召唤一轮援兵"，不写"多经历一轮阶段与差距相符"。
- **不确定的话只在一个地方说。** 正文里的结论要么证据够、直接下，要么不写。"不能断言""不能据此""未核实""不代表""仍待核对"这类话只能出现在"还没看清的"和附录里。正文一条结论最多用一次"很可能"。
- **一句话一件事，多用短句。** 一句话里出现两个"但"或"不过"，就拆开或删掉。
- **对事不对人，先说做得好的。** 说行为（"#7 大减伤在上一波用掉了"），不说评价（"坦克不会用减伤"）。

### 空话清单：出现就重写
| 空话 | 改成 |
|---|---|
| 注意减伤 / 准备减伤 | 哪个减伤、谁开、看到哪个读条时开 |
| 集中爆发 / 提高输出 | 在哪个时间点之前打掉多少血；打首领本体的 DPS 从多少提到多少 |
| 提前准备 / 加强沟通 / 合理分配 | 写出具体分工：谁负责什么 |
| 优先处理小怪 | 先杀哪只、为什么、谁来杀 |
| 注意走位 / 躲技能 | 哪个技能、从哪里躲到哪里、参考被打中几次 |
| 需要进一步核实 | 放进"还没看清的"，写清用哪条命令核实 |

### 好坏对照（副本、技能和数字都是虚构的，只示范写法）
**首领战慢**
- 差："首领甲比参考慢 55 秒，多经历了一次阶段转换，不能据此断定是谁的输出问题。建议集中爆发，争取提前击杀。"
- 好："首领甲 3:10，快的参考 2:15。首领血量每场一样（都是 90M），差别在有没有赶上门槛：开怪约 2:20 时她会第二次飞上天、召唤一轮援兵。本场没在这之前打死，多打了一整轮小怪（多 50M 伤害），用时多出将近一分钟。要在 2:20 前打死，打首领本体的团队 DPS 要从 460K 提到 650K。下一把：嗜血和三名输出的大技能全部在开怪时交给首领；第一轮援兵交给 AOE 职业顺带清，另外两人援兵一倒立刻转回首领。复验：首领战 ≤ 2:20，只召唤一轮援兵。"

**死亡**
- 差："坦克在 #7 被多个来源同时攻击后死亡，减伤使用情况需进一步核实，建议提前准备减伤。"
- 好："#7 坦克 1.5 秒内从 80% 掉到 0：两只岩石卫士的'重击'同时落下，各 600K。参考拉这一波时，坦克在第一次'重击'读条时就开了大减伤；本场坦克的大减伤 40 秒前在 #6 用掉了，还没转好。下一把：#6 不交大减伤，靠小减伤和走位过；#7 看到第一次'重击'读条就开。复验：#7 坦克血量不低于 30%。"

## 其他写作要求
- 用中文，技能名用游戏内的中文名，第一次出现时附技能 ID。
- 具体：写"第 2 段 #10 波 1:04，参考同样这些怪约 6 秒（重拉）"，不要写"小怪偏慢"。
- 给队伍的口令用波次和读条信号，不用绝对时间（首领战内部的"开怪后 X 秒"可以用）。
- 不要把同一件事拆成好几条写，也不要在几节里重复讲同一件事。"时间丢在哪里"和"差点出事的地方"讲到同一次团灭时，在一处详细写，另一处一句话带过。

## 交付前自检
- [ ] 分段表的数字照抄 `splits`（累计差是各参考累计差的中位数，各段"本段差"相加不等于它，这是正常的，不用解释）；参考记录的可比性写在了附录。
- [ ] "时间丢在哪里"每一条都有位置、数字和原因，并且按丢的时间排了序。
- [ ] 死亡总数和报告里讲到的死亡对得上（连续死亡可以合并成一条讲）。
- [ ] "下一把怎么打"每一条都核实过对应的时间窗口，并且写清了谁、什么时候、做什么。
- [ ] 写"有减伤没交"之前，可用性表显示"可用"；缺席时长以"回归"列为准。
- [ ] 没有因为连锁死亡追究个人，没有把一条因果链拆成多条。
- [ ] "时间丢在哪里"和"下一把怎么打"的每一条都走完了五步（现象、参考怎么打、为什么、口令、复验）。
- [ ] 正文里没有空话清单里的词，也没有"不能断言""未核实"这类话（它们只出现在"还没看清的"和附录里）。
- [ ] 把报告念给一个没看过日志的队友听，他能说出下一把自己要做的那件事。
