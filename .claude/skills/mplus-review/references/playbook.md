# 大秘境复盘方法论

本文讲怎么从 `wcl` 的客观数据里判断问题、给问题排序、提出改进。数据口径和"检查 → 数据 → 补查 → 无法观测"对照表见 `data-notes.md`，评分见 `scoring.md`，报告结构见 `report-template.md`。

## 1. 核心原则
- **时间是货币。** 优先找改变结果的问题：能不能限时、能不能升到 +2/+3、会不会翻车。其次才是"打得更漂亮"。
- **评判执行，不评判路线。** 路线和拉怪规模是队伍的选择，要评价的是在这个选择下执行得怎样。只有数据明确显示某个选择直接导致了灭团或大量时间损失，才讨论路线，而且写成"可以尝试"的假设。
- **先确认数据能用，再下判断。** 计数自相矛盾（打断 > 读条）、样本太小（同层只有几个人）、输出被截断、口径不清，这些情况下的指标不能用来下结论。在报告里写明"该指标不可用"，而不是硬套。
- **基准优先于绝对阈值。** 判断"多不多、慢不慢、该不该断"，先看 `compare`（同层高分记录）和 `spec`（同专精顶尖），再看队内对照。本文里的数字是"值得深挖"的触发线，不是合格线。
- **先解释死亡和灭团，再解释节奏和资源，最后解释活着时的循环效率。**
- **一条因果链只算一次。** 一次漏断引发的伤害、死亡、罚时，写成一个主问题加若干贡献因素，不要拆成几个问题重复追责。评分里也一样：死亡的后果只在生存里扣。
- **证据够了就下结论**（门槛见 §2）。达到门槛的问题直接写明确的判断和要求，不要处处加"可能"。证据不足时写"待验证"，并给出验证用的命令。
- **建议要具体到人、时机和动作**，不写"注意走位""多打断"。
- **先肯定做得好的执行**，例如关键读条全断、首领战比高分快、战复及时。
- **不编造机制。** 不认识的技能先查 Wowhead（见 `data-notes.md`）。查不到时，只描述数据里能看到的现象，并标注"机制未核实"。

## 2. 证据与置信度
置信度分两种，分开写：
- **事实置信度**：事件本身发生过没有。`deaths`/`events` 直接给出的时间线即为高置信，例如"11:38–11:44 被放血打中 7 次"。
- **归因置信度**：为什么发生、是谁的问题。

| 归因置信度 | 门槛 |
|---|---|
| 高 | 时间线已核实，并满足其一：(a) 有基准对照支持（compare/spec/队内对照）；(b) 事件里有完整因果链（原因事件 → 中间的伤害或减益 → 后果）。同时，主要的替代解释已经排除 |
| 中 | 两个以上独立信号一致，但时间线或机制有一环没核实 |
| 低 | 只有单一汇总信号、单一样本、跨层比较，或机制未知 |

- "最值得改进的 3 件事"只收中、高置信的问题；低置信的放进"待验证"。凑不满 3 件就写 2 件，不要为了凑数降低门槛。
- "先发生"不等于"导致"。要把漏断和死亡连起来，需要看到中间的伤害或减益事件。
- 缺失不等于零：没有排名数据、没有基准、事件为空，要和"真的没用/没发生"区分开。

## 3. 影响排序与时间账本
### 3.1 排序
默认初筛顺序：**灭团/重开 → 死亡 → 大段时间损失 → 关键漏断 → 可躲承伤 → 资源使用（嗜血/减伤/药水）→ 输出循环**。
最终排序看四点：实际后果（秒数或翻车风险）、会不会再发生、证据强度、下次能不能改。

### 3.2 时间账本（写成区间，并注明假设）
- **罚时**：死亡次数 × 每次罚时，已经算在官方用时里。`overview` 给出"扣除罚时后的用时"，拿它和高分记录比，可以分清"问题在死亡"还是"问题在节奏"。
- **死亡缺席**：从死亡到 `deaths` 里"回归"列给出的第一次动作，这是缺席时长的上界。不要默认缺席到该波结束。缺席造成的等效输出损失 ≈ 缺席秒数 × 该玩家 DPS ÷ 团队 DPS。坦克或治疗死亡的主要代价是减员和连锁，写后果，不硬换算成秒数。
- **灭团**：只计算需要重打的部分：失败那次首领战的时长（`pulls` 里该首领 kill=false 的那次），加上从失败到重新开打的间隔。小怪波次灭团时，已经杀掉的怪不会复活，不要把整波都算作损失。
- **长间隔**：先用 `events --from --to` 看间隔里发生了什么，例如交互、移动、复活、等冷却、喝水。核实是无意义的等待之后，才把它算作可省的时间。
- **用时对比**：`compare` 的首领战用时、小怪合计、战斗中/脱战与高分中位数之差，只作为排查线索。差距里已经包含死亡、低输出等原因，不要再逐项相加。
- **怪物进度溢出**：最终进度明显超过 100%（例如 >103%）时，可以作为可选的提速点提一下。但多拉可能是路线需要，不算错误。
- 承伤、漏断这类没有可靠时间模型的问题，写后果（治疗压力、死亡风险），不硬换算秒数。

## 4. 怎么用基准
- 先记录可比性：对方的层数、阵容、装等（`compare` 表头）、样本数。同层前排可能是同一支队伍的多场记录；低层前排往往是装等远高于本队的速通。
- **可以跨层比的**：命中次数、每次施放命中、打断率、CPM、用时结构，而且要满足"机制一致"的前提。**不能跨层比的**：伤害和治疗的绝对数值。
- "每次施放命中"是事件比值，不等于中招人数，只对"一次施放打中少数人"的技能有意义。光环和持续型技能一次施放会反复命中，要按战斗时长比较，`score` 的候选列表已经这样处理。
- 小怪技能的总命中受路线影响，只有确认双方都拉了同类怪、拉的数量相近时才比较。
- 高分记录之间差异很大的指标（例如 30/0/0），说明它和打法或路线有关，不能当作标准。看中位数，不看单场。
- 没有可用基准时，用队内对照（同一技能，其他队员被打中几次）和本场重复出现的同类情景，并降低置信度。

## 5. 分维度诊断
每节按"看哪里 → 什么信号 → 怎么确认 → 怎么改"展开。

### 5.1 计时与节奏（`overview`、`pulls`、`compare`）
- 看：余量与 +2/+3 差距（+2 = 限时 80%，+3 = 60%）、罚时、扣除罚时后的用时、首领战与小怪用时、最长间隔、首领战灭团、怪物进度、嗜血。
- 首领战比高分中位数慢 >10%：先查死亡、灭团、DPS 在不在线，再查转阶段或机制。
- 某段间隔明显长于本场常态：按 §3.2 先拆清楚，再判断。
- 大波怪持续很长但没有死亡：看团队 DPS 是否在后段明显下降（残血怪拖尾、爆发交空）。
- **嗜血/英勇**：看 `pulls` 的嗜血列。通常应该用在本场最危险或最长的大波，或者需要压血线的首领上。值得指出的情况：用在低压力的小波；死亡或灭团最集中的那一波反而没开。不要机械要求"开怪就开"。
- 怎么改：指出具体的波次和时机，例如"第 8 波（本场最长、死亡 1 次）开嗜血，第 1 波改用团队爆发"。

### 5.2 死亡（`deaths` → `events` → `player`）
- 每次死亡的证据包：时间与波次、致死技能与来源、死前血线（`剩x%`）、承伤构成、受到的治疗与护盾、死者死前 15 秒的施法、获得的增益、技能可用性表、回归时间、属于哪一串。
- 先检查完整性：`deaths` 的死亡总数与已展开的编号是否一致。被截断时，用 `--detail` 或 `events` 分段补查，不要把没看到的死亡当作没发生。
- **归因分类**（和评分的 `cause` 一致；一个主因 + 若干贡献因素）：
  | 归因 | 典型证据 |
  |---|---|
  | 个人可避免 `personal` | 站在已核实可躲的伤害里（`damage --ability` 看受伤段）；或者死前有掉血窗口，而可用性表显示减伤/治疗石"可用"却没交 |
  | 部分责任 `shared` | 伤害叠加（2–3 秒内几个来源重合）、治疗或打断也有缺口，个人的应对只是其中一环 |
  | 连锁/他人/不可躲 `chain` | 坦克或治疗先倒后随即死亡；不可躲的瞬间秒杀；团灭里的后续死亡 |
  | 未能核实 `unknown` | 证据不足以区分以上几类 |
- **常见根因的识别**：
  - 可躲机制：致死技能或主要承伤是某个技能，`score` 的候选或 `compare` 显示本场明显多于高分，`damage --ability` 显示死者在受伤段里停留。
  - 坦克被打穿：短时间多源近战或技能叠加，看 `player <坦克>` 的低频技能时间轴，以及死前获得的增益里有没有主动减伤。
  - 治疗跟不上：血线持续下降、有数秒救治窗口，但受到的治疗很少。同时检查治疗当时是否在处理机制、是否也在掉血或已经倒下。
  - 漏断引发：用 `events --type enemy-casts --from <死前30秒>` 找读完的读条，再看后续的伤害或减益。读条、减益、伤害的技能 ID 常常不同，按名称和时间先后对应。
  - 站位/仇恨：非坦克吃到近战或正面技能时，先用 `events --type debuffs --player <受害者>` 查有没有锁定或点名类减益。查不到也只能写"疑似未拉住"，置信度不超过中，不进入 3 件事。
- **自保是否"有却没交"**：只有可用性表显示"可用"，才能这样写。判定方法：距上次使用 ≥ 本场最短间隔，就一定不在冷却。还要注意两点：
  - 死前更早获得、仍在持续的减伤也算覆盖，要看"获得的增益"和 `events --type buffs`。
  - 充能类技能不适用这条规则；判定为"可能在冷却"或"无法判定"时，不能写"没交"。
- 致死一击不一定是根因。从死亡往前找"最后一次安全血量"，看血线是一次被打空（爆发：需要提前减伤或躲开），还是持续流失（存在救治或自保窗口）。
- **团灭**：看"连续死亡"表。串首往往是起因，但这只是候选，要按上面的方法核实。后续死者标为连锁，不要让每个人都为同一次团灭背锅。
- **战复**：看"复活"列，或用 `events --filter 'type = "resurrect"'` 查全场的复活事件。工具不显示战复充能，判断"该不该战复"时写"充能未核实"，不要指责没有战复。
- 怎么改（虚构示例）：'X 吐息'读条时离开正面；来不及时，如果个人减伤"可用"，在读条开始时开。

### 5.3 打断与控制（`interrupts`、`compare`、`events`）
- 看：每个技能的读条/打断/读完/其他中止与"计数"列、漏断按波次的分布、每人纯打断与控制打断、`compare` 的打断率对比。
- "计数"列标"不一致"的技能，打断率不可靠，不要据此下结论。
- 高分打断率高（≥70%）而本场读完多的技能：首要目标。高分队伍也很少打断的技能，优先级低。
- 高分记录里没有出现的读条，按后果排优先级：读完之后有没有造成死亡或承伤峰值。
- **漏断集中在某一波时，先算容量**（`interrupts --pull N`）：
  1. 可用打断次数够、但有人没断或重复断 → 分工问题，写分工表。
  2. 已经一人一只、每人都接近按冷却在断 → 容量问题。改为：第一轮用群控（击倒、恐惧、盲目之光等）覆盖，优先击杀施法者，或者接受读完，改为安排驱散和减伤。
  3. 再看后果（该波承伤、死亡）决定优先级。
- 某人纯打断明显少于队内中位数：先确认他有没有打断技能、冷却多长、是否在承担其他职责（坦克拉怪、治疗救人），再下结论。
- "施放−打断计数"偏高，可能是重复打断、打在没读条的怪上，或者反应慢。指定打断顺序和报断习惯可以改善。
- WCL 把击倒、恐惧、致盲等计入"打断"，"其他中止"里还包含控制和施法者死亡。不要把这些都当作纯打断的功劳。
- 怎么改（虚构示例）："第 N 波 4 只施法者：星/月/方块/三角标记，每人各断一只；第二轮由群控覆盖"。

### 5.4 承伤与机制（`damage`、`score`、`compare`、`events`）
- 看：每个技能的伤害、敌方施放、命中/跳、每次施放命中、每人分布与标记；`score` 的"暴露偏离候选"；`damage --ability` 的受伤段（谁、哪一波、停留多久）。
- 判断"可躲"的证据链：
  1. 归一化后，本场明显多于每一场高分记录（`score` 候选或 `compare`），或者队内只有个别人反复被打中。
  2. `damage --ability` 显示多出来的命中集中在某些人或某几段里。
  3. 机制核实：Wowhead 的技能说明，或者事件规律（读条后的正面、地面减益的出现与消失）。
  三条都满足为高置信；满足 1 和 2 为中置信。核实后写进 `judgments.avoidable`，只对部分职责可躲的加上 `roles`（例如正面技能对坦克不可躲）。
- "全员承伤接近"且高分记录也稳定命中的伤害，通常躲不掉，属于治疗和减伤规划问题：安排团队减伤和个人减伤的轮换，不要要求躲开。
- "坦克承受"类伤害看坦克的主动减伤和外部减伤。只有非坦克也被打中时，才考虑正面朝向和仇恨问题。
- 跳数异常多：说明在地面效果里停留太久，或者减益没有及时驱散。是否可躲、能否驱散都要先核实。
- 来源为"环境"的伤害多是场景机制或地面效果。
- 怎么改：写清楚"什么信号出现时、谁、做什么"，例如"看到 X 读条时近战退到背后"。

### 5.5 驱散与减益
- 看 `interrupts` 末尾的驱散汇总，以及 `events --type debuffs --ability <减益>`。
- 被驱散过至少一次的减益是可驱散的。如果同一减益多次在队员身上停留很久、跳很多伤害，或者引发了死亡，就检查驱散分工和驱散冷却。
- 不确定能不能驱散时查 Wowhead（Dispel type 字段），不要假设。

### 5.6 减伤、治疗石与药水（`player`、`deaths`）
- 低频技能时间轴（CPM ≤ 1.2）可以看出大招和减伤用了几次、最短间隔（接近冷却就是在按 CD 用）、每个首领战有没有用。不在表里的技能，用 `player <玩家> --ability <技能>` 查。
- 不能用"整场时长 ÷ 冷却"当作应交次数。要看有价值的时机：大波怪起手、首领高伤阶段、已知的伤害峰值。
- 可用性判定同 §5.2；"可能在冷却"或"无法判定"时不写"没交"。
- 治疗石和药水只有次数，没有时间点。需要时间点时用 `player --ability`。死前数秒掉血窗口里没用治疗石，并且它可用，是明确的改进点。
- 合剂、食物等：`player` 的增益覆盖率里能看到。整场缺失才值得一提。

### 5.7 输出与循环（`overview`、`player`、`spec`）
- 先看同层同专精百分位和样本量。**样本不可靠（< 20 人）时，百分位噪声很大**，改用"本人 DPS ÷ 同层同专精最佳成绩中位数"（`score` 的输出维度已经这样处理），或者看 `spec`。
- 百分位低只是触发排查：死亡缺席、承担大量打断或机制职责、目标数少、装等偏低，都会拉低它。先排除这些，再谈循环。
- **活跃时间是 WCL 伤害表的 activeTime，不是 GCD 利用率**，不同专精之间差异很大，不能单独拿来判断"停手"。只有和同专精顶尖比（`spec`）、并且对应到具体的停手窗口时，才有意义。
- `spec` 中核心技能 CPM 比顶尖中位数少 ≥30%：结合死亡缺席和具体窗口判断是停手还是技能顺序问题。"本场未使用/顶尖都不用"多半是天赋或打法不同，可以作为天赋参考，不是错误。
- 大招对齐：在 `player` 的时间轴里看大招有没有覆盖大波怪和首领。最长间隔明显大于最短间隔，说明某段时间留在了手里，但这只是排查信号：可能是在等大波。
- 怎么改：指向能观察到的动作，例如"第 4、9 波首领开场交爆发""大波怪等聚怪完成后再开爆发"。

### 5.8 治疗与坦克专项
- **治疗**：HPS 取决于全队受到的伤害，不代表治疗水平，也不计分。重点看三件事：每次死亡前有没有救治窗口、治疗当时能不能行动；全团伤害峰值有没有用大招覆盖（低频技能时间轴）；治疗压力有多少来自可躲伤害和漏断（这部分应该归到承伤者或打断分工上）。蓝量工具没有直接展示，"空蓝"的结论需要用 `query` 查资源，或者写成待验证。
- **坦克**：看坦克死亡、承伤高峰时有没有主动减伤和外部减伤、大波怪起手时的减伤安排、非坦克是否吃到近战（先按 §5.2 排除锁定）。坦克承伤高是职责，不是问题；问题在于高峰时有没有应对。

## 6. 最容易犯的错
- 死亡造成的低输出，算成了循环问题 → 先扣除缺席时间。
- 团灭后的一串死亡，人人追责 → 只追究起因，后续标为连锁。
- 只看致死一击 → 回看整段血线与叠伤。
- 跨层比较伤害数值，或按施放次数比较持续型技能 → 只比较机制一致的计数。
- 把罚时再加一次，或把战斗拖长当作"多吃了机制" → 官方用时已含罚时；命中先按暴露归一化。
- "未战复"就当作缺席到波次结束 → 以"回归"列为准。

## 7. 评分
1. 运行 `wcl score`（不带判断）查看数据分和"暴露偏离候选"。
2. 复盘过程中核实判断，写进 `judgments.json`：可躲技能、死亡归因、每名深挖过的玩家的技能运用。每条都带证据。
3. 运行 `wcl score --judgments judgments.json`，把结果放进报告。
- 输入不成立的维度为 N/A，照实写，并说明原因。有效权重不足时不发布总分。
- 分数必须和正文一致：被列入 3 件事的负责人，相关维度通常 ≤ 7.4，否则写明原因。
- 评分用于定位改进方向，不是给队友排名。

## 8. 写成具体的建议
每条问题统一按"**定位 → 事实 → 判断（含置信度）→ 后果 → 行动 → 复验**"来写：
- **定位**：第 N 波或首领、相关的人和技能、`m:ss`。给队伍的口令优先引用波次和读条信号，不用绝对时间（游戏内计时与 WCL 时间之间还隔着累计罚时）。
- **事实**：数字，写成"分子/分母"（例如"读完 18/22"），附对比样本的数量和范围。
- **判断**：主因、贡献因素、归因置信度。
- **后果**：罚时、失败尝试、缺席时长，或治疗压力和风险。
- **行动**：谁负责、谁配合、什么信号出现时做什么。
- **复验**：下一把检查哪个指标。

对比示例（人名、技能、数字均为虚构）：
- 差："DPS 多打断，别漏。"
  好："第 6 波 4 只施法者的'暗影箭'读完 18/22（同层高分该技能打断率 75%）；`interrupts --pull 6` 显示可用打断够，但其中 2 人整波各只断了 1 次。下把按标记一人一只：坦克 星、DPS-A 月、DPS-B 方块、DPS-C 三角，断完报'断了'。复验：第 6 波暗影箭读完 ≤3 次。"
- 差："治疗奶不住，注意自保。"
  好："14:02 玩家 A 在'腐蚀之池'里停留 5 秒（受伤段 14:02.1–14:07.0，11 跳），从 90% 掉到 0；同层高分每场只命中 2–4 次；可用性表显示个人减伤可用。归因：个人可避免（高置信，Wowhead 确认为地面效果）。下次脚下出现池子立刻移出，来不及就先开减伤。复验：该技能每场命中 ≤4 次。"
- 差："输出低，练练循环。"
  好："玩家 B 同层样本 100+ 人，百分位 15。`spec` 显示核心技能 X 的 CPM 为 5.3，顶尖中位数 6.4，活跃时间与顶尖持平；另有一次死亡，缺席约 40 秒（回归列）。建议优先检查技能 X 的触发使用。复验：技能 X 的 CPM ≥ 6.0。"
