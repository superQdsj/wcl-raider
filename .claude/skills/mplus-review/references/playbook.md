# 大秘境复盘方法论

复盘就像看录像：先把这一把从头到尾过一遍，找出时间丢在哪、哪里差点出事，再决定下一把改什么。本文讲每一步怎么看、怎么判断。数据口径见 `data-notes.md`，报告结构见 `report-template.md`。

## 1. 几条原则
- **以时间线为主线。** 报告按这一把的进程组织（第 1 段、第 2 段……），而不是按维度（打断、承伤、输出……）。维度只是用来解释"这一段为什么慢、为什么差点炸"的工具。
- **跟参考比，而且逐段比。** "首领战合计慢 3 分钟"没法行动；"第 2 段灭团后重拉了两波，多花了将近 2 分钟"可以。参考优先选路线相近的同层记录；用户自己上一把限时的记录是最好的参考。
- **扣掉整体快慢再看。** 排名靠前的记录装等往往高出一截，每一段都会更快。`splits` 的"按节奏折算超额"已经扣掉了这部分：超额大的段，才是本场特别慢的地方。整体都慢、各段超额都不大，说明是输出或装等的整体差距，不是哪一处打崩了，写成一句话就行。
- **路线是可以谈的。** 和参考比，本场多拉了什么、少拉了什么、哪几波拆开或合在一起拉，都是正当的复盘内容。但要尊重队伍的处境：阵容和装等不同，参考的大拉不一定适合本队。写成"参考都是这样拉的，本场是那样拉的，差了多少时间，可以试试"，而不是"路线错了"。
- **一条因果链只讲一次。** 一次漏断导致团灭、团灭导致重拉，写成一件事：起因、经过、代价。
- **只写能改的。** 每条结论都要落到"谁、在什么信号出现时、做什么"。"注意走位""多打断"不算结论。
- **先说做得好的。** 哪一段比参考快、哪个首领打得干净、哪次战复很及时，一两句就够。
- **不编造机制，也不靠记忆。** 讲到一个敌方技能（尤其是致死技能、反复造成险情的技能），先跑 `wcl ability <链接> <技能>`：它从本场和参考的日志里统计点谁、能不能打断/驱散、减益多久、参考死没死，并附上 Wowhead 的说明原文。日志统计和说明冲突时以日志为准。两边都说明不了的，只描述现象，并写明"机制没查到"。

## 2. 这一把是怎么打的（讲故事）
用 `overview`、`splits`、`pulls`、`danger` 把这一把讲出来。每一段写两三句话，内容是：
- 这一段用了多久、参考用了多久、到这个首领时累计落后或领先多少；
- 段里最重要的事：哪一波打得特别长、谁死了、有没有灭团或重拉、嗜血开在哪；
- 和参考相比拉怪有什么不同（`splits` 的"路线差异"）。

示例（虚构）："第 2 段（黄金风蛇 → 殓尸者姆沁巴）11:12，参考 6:53，到姆沁巴时累计落后 6:08。前 4 波每波都比参考慢 15–25 秒，是正常的输出差距；真正的问题在首领：第一次开怪 21 秒团灭，之后重拉了两波防腐液，加上第二次首领战，这一段多花了将近 3 分钟。"

讲完故事，时间丢在哪里通常已经很清楚了。讲不清的地方，就是接下来要追的地方。

## 3. 时间丢在哪里
### 3.1 找位置
- 先看 `splits` 的"分段用时"：**按节奏折算超额**最大的段是重点；累计差告诉你最终差距是怎么一点点积累起来的。
- 再看"波次对照"：段里哪几波的差值最大。重拉的波次（"全是之前出现过的怪"）整波都是多花的时间。
- 看"每段的时间花在哪"：多出来的时间是在小怪战斗、首领战、失败尝试，还是脱战里。

### 3.2 追原因
丢时间的原因基本就这几类，按这个顺序排查：

| 原因 | 信号 | 怎么确认 |
|---|---|---|
| 灭团 / 重拉 | 首领失败尝试；重拉的波次；一波里死 3 人以上 | `deaths` 找第一个倒下的人和起因（§4），`pulls` 看灭团到重新开打的间隔 |
| 死人导致这一波打不动 | 波次比参考慢，同一波有人死 | `deaths` 的"回归"列看缺席多久；坦克或治疗死了，往往整波都要拖 |
| 输出没打出来 | 波次比参考慢、没人死、承伤不高 | `pulls` 的团队 DPS 和嗜血列；`player` 看爆发有没有交在这一波；大波怪后段 DPS 掉下来 = 残血怪拖尾 |
| 停顿 | 脱战比参考长；`pulls` 里某段间隔明显长 | `events --from --to` 看间隔里在干什么：跑尸、等冷却、喝水、等人 |
| 拉法不同 | 路线差异；波次对照里"可比参考"少；本场波数多 | 对比参考怎么拉：合拉能省多少，本队能不能扛得住（看本场类似规模那一波的险情） |
| 首领战慢 | 首领击杀用时明显长于参考，且超过整体节奏 | 先看 `splits` 的"首领战：伤害打在了哪里"：首领本体承伤和参考一样、其他目标伤害多 → 多经历了一轮阶段/刷怪，找击杀门槛（快的参考在第几次阶段前打死），口令写成"开怪后 X 秒内打死，打首领本体的 DPS 要到 Y"；其他目标伤害差不多、首领 DPS 低 → 输出没打在首领上（看分人伤害和爆发时机）。再用 `events --pull N --type enemy-casts` 数阶段技能核实 |

- 灭团的代价 = 失败的那次尝试 + 从灭团到重新开打的间隔 + 重拉的波次。已经杀掉的怪不会复活；`splits` 里标着"之前出现过"的怪才是重拉。
- 死亡罚时已经算在官方用时里，`splits` 用的是实际时间，罚时单独列出。写代价时两者分开说："第 8 波团灭：重打和重拉约 2:20，外加 5 次死亡罚时 1:15"。
- 怪物进度明显溢出（>103%）时，多出来的那部分怪就是可以省下的时间。但多拉的怪也可能是为了路线方便，要结合参考判断。
- **嗜血**：应该交在最长、最危险的大波，或者需要冲 DPS 的首领上。值得指出的情况：交在了低压力的小波；本场最慢、死人最多的那一波反而没开。

## 4. 哪里差点出事
### 4.1 找位置
- `danger` 的"按波次"表：险情和死亡集中的波次，就是这条路线上最危险的地方。
- **团队险情**（多人同时低血）比单人险情更重要：它说明团减、群疗、打断或躲技能里有一环没跟上，下一把很可能直接团灭。
- 同一个人反复出现在险情里，说明问题是习惯性的，比如站位、减伤习惯或治疗分配。
- 同一个技能反复把人打到低血：先查它躲不躲得掉（§4.3），再决定是要求躲，还是要安排减伤。

### 4.2 死亡和团灭：找第一张倒下的骨牌
- 每次死亡要看的证据：时间与波次、致死技能、死前血线（`剩x%`）、死前几秒的承伤构成、受到的治疗、死者死前的施法、获得的增益、减伤可用性表、回归时间、属于哪一串连续死亡。
- 先检查完整性：`deaths` 的死亡总数和展开的条数是否一致。被截断就用 `--detail` 或 `events` 补查。
- 致死一击不一定是根因。往前找"最后一次安全血量"：是一下被打空（爆发伤害，需要提前减伤或躲开），还是持续掉血（中间有救的窗口，要看治疗和自保）。
- **团灭**：看"连续死亡"表，串首往往是起因，但这只是候选，要核实。后面倒下的人标为连锁，不要让每个人都为同一次团灭负责。
- **致死技能先画像**：`wcl ability <链接> <致死技能>`。画像会告诉你它是不是"只点某个职责"、能不能断/驱、参考有没有因它死人。参考吃了同样次数却没人死时，答案就在参考那几秒里：用 `events <参考链接> --from --to --player <参考里中招的人>` 看他们开了什么减伤、谁给了外部减伤、血线怎么样，把这个写成本队的口令。
- 常见根因：
  - **可躲机制**：致死技能或主要承伤来自某个技能，`compare` 显示本场被打中的次数明显多于参考，`damage --ability` 显示死者在受伤段里停留。
  - **漏断**：`events --type enemy-casts --from <死前30秒>` 找读完的读条，再看后续的伤害或减益。读条、减益、伤害的技能 ID 常常不同，按名称和时间先后对应。只有看到中间的伤害或减益，才能把"漏断"和"死亡"连起来。
  - **坦克被打穿**：短时间内多个来源叠加。看 `player <坦克>` 的低频技能时间轴，以及死前获得的增益里有没有主动减伤。
  - **治疗跟不上**：血线持续下降，有几秒能救的窗口，但受到的治疗很少。同时检查治疗当时是不是在处理机制、自己是不是也在掉血或已经倒下。
  - **仇恨/站位**：非坦克吃到近战或正面技能时，先用 `events --type debuffs --player <受害者>` 查有没有锁定或点名类减益。查不到也只能写"疑似没拉住"。
- **"有减伤没交"**：只有可用性表显示"可用"才能这样写（距上次使用 ≥ 本场最短间隔）。死前更早开的、仍在持续的减伤也算交了；充能类技能不适用这条规则。"可能在冷却""无法判定"时不要这样写。
- **怎么回来的**：`deaths` 的"复活"列已经分好类：战复（谁用什么技能）、自我复活、"没人复活 → 释放灵魂跑尸"。跑尸时"回归"只是在墓地复活的时间，回到队伍还要跑路，缺席比"回归"更长。工具不显示战复充能，涉及"该不该战复"时写"充能没核实"。
- **"0% 没死"**：`danger` 标了"免死"的，是炼狱、灸灼这类免死效果挡住了致死伤害：按"本该死一次"处理，它说明这一下伤害足以秒人，下一把免死不一定转好。

### 4.3 打断与可躲伤害（只在解释险情、死亡、慢波时用）
- **该不该断**：`compare` 里高分记录打断率高（≥70%）、本场读完多的技能是重点；高分队伍也很少断的技能，优先级低。"计数"列标"不一致"的技能，打断率不可靠。
- **漏断集中在某一波时，先算容量**（`interrupts --pull N`）：
  1. 可用的打断次数够，但有人没断或者重复断 → 分工问题，写分工表。
  2. 已经一人一只、每人都接近按冷却在断 → 容量问题。改成第一轮用群控（击倒、恐惧等）覆盖、先杀施法者，或者接受读完，提前安排驱散和减伤。
- WCL 把击倒、恐惧、致盲等也计入"打断"，统计时要和纯打断分开。
- **躲不躲得掉**的证据链：(1) 按战斗时长归一化后，本场明显多于每一场参考（`compare`、`score` 的"暴露偏离候选"），或者队里只有个别人反复被打中；(2) `damage --ability` 显示多出来的命中集中在某些人、某几段；(3) 机制已核实（`wcl ability` 的说明原文和画像，或者事件规律，比如读条之后的正面技能、地面效果）。满足 (1)(2)(3) 就可以明确要求躲；只满足 (1)(2) 时写"很可能躲得掉"。
- 全员承伤接近、高分记录也稳定吃到的伤害，一般躲不掉，属于减伤和治疗的安排问题：给出团减的轮换方案。
- 可驱散的减益停留很久、跳很多伤害，或者引发了死亡：检查驱散分工。能不能驱散看 `wcl ability` 的画像：所有记录 0 次驱散 = 基本不能驱散，这时别要求驱散，改成减伤和治疗安排。

## 5. 下一把怎么打
写法见 `report-template.md` 的"话术"一节（五步写法、空话清单、好坏对照）。
- **最多 3 条**，按"能省多少时间 / 能降低多少翻车风险"排序。凑不满就写 2 条。
- 每条写成能直接在语音里布置的话：**什么时候（第几段第几波、看到什么读条）→ 谁 → 做什么**，再加一句为什么（这把在这里丢了多少时间，或者差点出了什么事）和下一把看什么指标。
- 给队伍的口令优先用波次和读条信号，不用绝对时间（游戏内计时和 WCL 时间之间还隔着罚时）。
- 证据不够硬的放到"还没看清的"里，写明要看什么、用什么命令看，不要写成要求。

对比示例（人名、技能、数字均为虚构）：
- 差："减少死亡，注意躲技能。"
  好："**姆沁巴开怪前先清掉防腐液那波，并且留团减**（坦克 + 治疗）。这把第一次开怪 21 秒就团灭了：开场 'X 读条' 读完，3 人在 4 秒内从满血掉到 0，那时团减已经在上一波用掉了。重打加上重拉两波，多花了约 2:20。下一把：开怪前确认治疗的团减转好了，'X 读条' 第一次读条时交。复验：首领一次过，开场 15 秒内没有人掉到 30% 以下。"
- 差："DPS 多打断。"
  好："**第 6 波 4 只施法者按标记各断一只**。这把第 6 波 '暗影箭' 读完 18/22，其中 2 人整波各只断了 1 次（打断够用，是分工问题），这一波比参考慢 40 秒，治疗也有 2 次险情。分工：坦克 星、A 月、B 方块、C 三角，断完报一声。复验：第 6 波暗影箭读完 ≤3 次。"

## 6. 个人表现
只写和上面几件事有关的人，例如串首、反复出现在险情里的人、负责关键打断或减伤的人、用户关心的人。每人 2–3 条，先说做得好的。
- 输出：先扣掉死亡缺席，再看爆发有没有交在大波和首领上（`player` 的低频技能时间轴），最后才看循环（`spec`）。同层同专精样本少于 20 人时，百分位噪声很大，不要用它下结论。活跃时间不是 GCD 利用率，只能和同专精顶尖比。
- 坦克：承伤高是职责，不是问题。要看承伤高峰时有没有主动减伤和外部减伤，以及大波开怪时的减伤安排。
- 治疗：HPS 取决于全队吃了多少伤害，不代表治疗水平。要看每次死亡前有没有救的窗口、治疗当时能不能行动、团队险情有没有用大招覆盖，以及治疗压力有多少来自可躲伤害和漏断（这部分应该算在承伤者或打断分工上）。

## 7. 最容易犯的错
- 把每个维度都检查一遍写成报告 → 只写回答四个问题需要的内容。
- 拿装等高一截的速通记录逐项比，结论变成"处处都慢" → 看按节奏折算超额。
- 把死亡造成的低输出算成循环问题 → 先扣掉缺席时间。
- 团灭后的一串死亡人人追责 → 只追究起因，后续标为连锁。
- 只看致死一击 → 回看整段血线和叠伤。
- 把罚时再加一遍 → 官方用时已经包含罚时；`splits` 的实际时间不含罚时。
- 跨层比较伤害绝对值 → 只比较次数、比率和用时结构。
