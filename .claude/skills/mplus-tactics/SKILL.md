# 大秘境应对技巧复盘

你在看一场打得好的录像，目的不是挑错，而是**把高手处理机制的方法抄下来**。要回答三个问题：

1. **这个副本有哪些需要"额外处理"的机制？**——会上减益、点名、读条、地面、击退/定身/恐惧的首领和小怪技能。
2. **高手用了什么技能来处理，时机是什么？**——哪个职业、哪个技能（以及它依赖的天赋），是在读条时预开、上身后立刻解，还是掉血后保命。
3. **换成我们的队伍怎么照做？**——按职业列出能直接用的做法；没有对应职业时，谁能替代。

数据只说明"在什么时候用了什么、之后发生了什么"。"为什么这样用"要靠技能说明（Wowhead）和副本机制来解释，写清楚哪些是数据直接证明的，哪些是推断。

用户输入：$ARGUMENTS

## 工具
数据工具与 `mplus-review` 共用：`python3 <仓库>/.claude/skills/mplus-review/scripts/wcl.py`（本 skill 目录的上一级里的 `mplus-review/scripts/wcl.py`），下文简写为 `wcl`。凭据报错时把报错里的配置步骤转告用户；"无权查看"表示私密报告。

| 命令 | 回答什么 |
|---|---|
| `wcl find <副本名> [--class <职业>] [--level N]` | 没有链接时：找带日志的高分记录（带职业时只找有该职业的记录），给出链接 |
| `wcl runs <链接>` | 报告里有哪几把钥石 |
| `wcl tactics <链接>` | **主线**：额外技能清单、每次使用的情境与直接效果、敌方机制 → 应对手段、敌方减益怎么结束的 |
| `wcl tactics <链接> --refs 3` | 再拉 3 场同副本同层高分记录，做多场对照（哪些做法是共识） |
| `wcl tactics <链接> --ref <链接>` | 指定对照记录，例如用户自己的记录 |
| `wcl tactics <链接> --ability <技能> [--player <玩家>]` | 某个技能每一次使用的情境：血量、身上减益、前后几秒敌方读条、效果 |
| `wcl tactics <链接> --player <玩家>` | 只看某名玩家 |
| `wcl tactics <链接> --class <职业> [--refs 2]` | **职业专题**：只看该职业（法师、冰法、奶骑…），对照记录从该职业的个人排名里取；末尾"七、职业汇总"跨场合并：技能 → 在哪用、什么时机、当时在吃什么伤害；**按位置**（每个首领/小怪段用了什么、当时敌人在读什么）；机制 → 怎么应对；该职业身上的减益怎么结束的 |
| `wcl spell <技能ID…>` | Wowhead 技能说明与驱散类型（敌方技能、玩家技能都能查） |
| `wcl render <报告.json> [--pdf …] [--png …] [--md …]` | 把报告 JSON 排成本地 HTML，并检查写作规则；可导出 PDF / PNG |
| `wcl events --from m:ss --to m:ss --type …` | 原始事件，核实某个窗口 |
| `wcl pulls <链接>` / `wcl overview <链接>` | 波次与首领、阵容（给情境定位用） |

口径见 `../mplus-review/references/data-notes.md` 的「应对技巧（tactics）」一节。

## 预算
WCL API 每小时 1000 点，stderr 会打印已用点数，数据有缓存。`tactics` 单场首次约 15–40 点（层数越高、战斗越长越多）；`--refs N` 每多一场再加约 20–40 点，外加排名查询（`find` 约 1–3 点）。本小时剩余不足 150 点时不要开 `--refs`，用单场数据完成并说明。随时可以用 `wcl points` 查余量。

## 流程
开始前读 `references/method.md`（证据怎么读、常见误判）；解释技能时查 `references/class-counters.md`；写报告按 `references/report-template.md`。

先判断问题类型：问的是某个**职业**（"法师在 X 副本该怎么应对"）→ 走下面的"职业专题"流程，报告 `kind: "class"`；否则按 1–6 步，报告 `kind: "team"`。

1. **定场次**：`wcl runs`。链接带 `#fight=N` 就用它；否则默认最后一条完成的钥石；多场时列出来问。用户只给了副本名没有链接时，用 `wcl find <副本名>` 找高分记录，取第 1 条，再用 `--refs` 拉对照。
2. **跑主线**：`wcl tactics <链接>`；用户想要"这个副本的通用打法"或记录只有一场时，加 `--refs 3`（预算允许）。用户给了自己的记录，就用 `--ref <自己的链接>` 对照。
3. **挑候选技巧**（method §2）：从"敌方机制 → 应对"表、"团队同时应对"表和每名玩家的表（含"常连用"）里挑 6–12 条。优先级：多队共识（对照表里"t 队"≥ 2）> 直接效果（驱散/免疫/反射/推断消除）> 强伴随。爆发技能、副本按钮/副本效果先放一边（单独成节）。
4. **逐条核实**：
   - `wcl tactics <链接> --ability <技能> --player <玩家>` 看每一次的情境：是预开（敌方读条后、减益上身前）、上身后解，还是低血保命。
   - `wcl spell <敌方技能ID>` 读机制：驱散类型、持续、效果（定身/减速/恐惧/点名/流血…）。ID 在 `tactics` 第一、二节的表里。
   - `wcl spell <玩家技能ID>`，再对照 `references/class-counters.md`：这个效果是技能本身的，还是需要天赋（例如假死要"紧急药膏"才清中毒/疾病，牺牲祝福要"正义保护"才清中毒/疾病，反魔法护罩要"不屈意志"才移除魔法）。日志里看不到天赋，只能从行为推断，要写明。
   - 证据只有"伴随"的，必须用 `--ability` 或 `events` 看过具体几次，确认时间关系说得通，否则写进"还没看清的"。
5. **补充机制资料**：首领/小怪技能的说明不清楚时，用 WebSearch 或抓取 `https://www.wowhead.com/spell=<ID>`（中文页常常抓取失败）。简单的查证（例如"某天赋现在还在不在"）可以交给子代理并行做。
6. **写报告**：按 `references/report-template.md` 写一份 JSON（照 `references/example-team.json` 改），然后 `wcl render <json>` 生成 HTML。检查报错就按提示改 JSON，再重跑，直到通过。读者是要照着打的玩家：正文按副本流程走，讲"看到什么 → 谁 → 按什么 → 为什么"；证据、时间戳、核实命令都放 `appendix`。

用户指定了玩家/首领时，只展开相关的机制和技巧，其他一句话带过。

### 职业专题（用户问某个职业）
1. **找记录**：用户给了链接就用它；否则 `wcl find <副本名> --class <职业>`（用户提到层数就加 `--level`），取排名第 1 条作主场次（这里不用第 1 步"最后一条钥石"的规则）。
2. **跑汇总**：`wcl tactics <第 1 条链接> --class <职业> --refs 2`（共 3 场；预算紧时 `--refs 1`）。只读末尾"七、职业汇总"，前面一至五节只是主场次：
   - **技能 → 用在哪**：决定工具箱放哪些技能。
   - **按位置**：决定"按副本流程"每张表写什么。这是正文的骨架：某个位置某个技能 ≥ 2 场都用、"用前敌方读条"或"当时在吃的伤害"有 ≥ 2 倍的敌方技能，就是一条"信号 → 按什么"。
   - **身上的减益**：决定"🩹 常中的减益"那张表。"一般怎么处理"那一列：工具只给出实际是谁解的，再用 `references/class-counters.md` 的"谁能解什么"补上能解的职业。
   - 时机怎么翻成报告用语、各职业减伤的性质：见 `class-counters.md` 的"个人减伤怎么读"。
3. **筛技能**（工具箱）：
   - 放进来：驱散、自解、免疫、减伤、位移、解控这几类，并且 ≥ 2 场都用过的技能。同名的两个 ID（例如操控时间的施放和回溯）在汇总里已合并，按一个技能写。减伤即使多数是"冷却好就用"也放进来，"时机"列就写"冷却好就用"或"大伤害前"。
   - 不放：输出、增益、饰品、消耗品、副本道具。工具已把这些列在"未列入"那一行；不认识的先 `wcl spell <ID>` 查。
4. **核实**：先读 `references/class-counters.md`（必读：天赋改变效果、个人减伤的性质、时机怎么翻译）。挑 3–6 条要写进正文的，用 `wcl tactics <链接> --class <职业> --ability <技能>` 看逐次情境（默认列前 40 次，`--detail N` 看更多）。"按位置"表是多场合计，主场次里可能恰好没有；`--ability` 只看传入的那一场，要核实别的场次就换成那一场的链接（第七节开头列了各场的报告代码）。机制名不清楚就 `wcl spell <敌方ID>`；技能的特殊效果（例如护体解减速要天赋「充能护体」）查 `references/class-counters.md`。读法：
   - 减伤、护盾、回溯（操控时间）类：用完之后**照样被打中是正常的**，被打中的那个技能正是它在顶的伤害，不是失误。
   - 只有免疫类（寒冰屏障、圣盾）才看"用后还被不被打中"。
   - "⚠️ 别这样做"只写数据里真看到坏结果的：死亡，或者没开减伤、几秒后掉到 20% 以下。不要从"用了之后还被打中"推出失误。
5. **补全**："身上的减益"表说明这个职业常中什么、谁解的，结合 `class-counters.md` 写"自己能不能解"。
   - 看"技能 → 用在哪"表的"专精"列：只有某个专精才有的技能（例如只有奥术用棱光护体），在工具箱里写"（奥术）"，常用度按该专精的场次算。数据里只有部分专精时，写明其余专精没有数据。
   - 每支队伍只有一名该职业玩家时，"两队都这样"其实就是"两名玩家都这样"，写"两名法师都这样"。
6. **写报告**：JSON `kind: "class"`，照 `references/example-class.json` 改，再 `wcl render`。正文只写这个职业；别的职业只在 `debuffs[].handling` 里出现。

**文件名**（两种报告统一）：日期一律用主场次的钥石日期（`tactics` 标题里的日期），存在仓库根目录（`.claude/` 所在的目录）的 `reviews/` 下，不管当前 shell 在哪个子目录。
- 整队版：`reviews/<日期>-<副本>-+<层数>-tactics-<报告代码>-f<fight>.json`
- 职业专题：`reviews/<日期>-<副本>-<职业>-tactics.json`

`render` 在同一位置生成同名 `.html`。用户要 PDF 或图片时加 `--pdf <同名.pdf>` / `--png <同名.png>`（PDF 含附录，PNG 是不含附录的整页长图）。

## 交付
对话里给：3–5 行要点（⭐ 那几条，一条一行："信号 → 技能：为什么"），以及 HTML 文件的绝对路径（导出了 PDF / PNG 的也给出路径）。不要在对话里再贴一遍报告内容。
