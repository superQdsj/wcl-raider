# 大秘境职业应对手册

手册是**攻略**，读者是要上场的玩家：看到什么 → 按什么 → 为什么。它不是复盘：不评价这几场打得好不好，不比时间，不看全队。

主线是**本职业的工具箱**：每个非伤害技能（免疫、减伤、驱散、外部技能、控制、打断、位移、嘲讽、破盾）在这个副本里被高手用在哪个机制上、给了谁、为什么有效。价值全部来自「高手在这本里额外做了什么」，不是通用减伤轮换。**先从证据表挑行，再补少量通用内容**，顺序不能反。

用户输入：$ARGUMENTS

## 工具（全部在本 skill 的 `scripts/`）

| 命令 | 作用 |
|---|---|
| `collect.py <职业目录> <副本> [--hero X] [--runs URL URL URL]` | 选三场录像写进 `sources/guide.db`（需要 WCL 凭据，消耗 API 点数） |
| `evidence.py <职业目录> <副本>` | **证据表**：本职业每个技能的次数、冷却、给谁、伴随机制、直接效果、位置、连用，加机制事实和身上减益 |
| `evidence.py … --ability <技能>` / `--mechanic <机制>` | 逐次施放明细 / 某机制每次读条前后本职业按了什么（量时机） |
| `evidence.py … --sql "SELECT …"` | 直接查库，表结构见 `guidelib.py` 的 `SCHEMA` |
| `build.py <职业目录> --dungeon <副本> [--output-dir D] [--png]` | 构建 HTML（全部图标内嵌），`--png` 导出长图 |

`<职业目录>` 写 `warrior-arms` 即指 `guides/warrior-arms/`。数据和技能说明（Wowhead 中文，含冷却、驱散类型）都存在库里，缺的会自动补。API 点数每小时 1000：采集前先跑 `python3 .claude/skills/mplus-review/scripts/wcl.py points`；已采集的副本不要重采。

这里只把 `wclr` 当数据库用。不要去读 mplus-review 或 mplus-tactics 的说明，它们讲的是复盘，与手册无关。

## 新职业：按需新建，不复制别的职业目录

在 `guides/<职业-专精>/`（英文，如 `holy-paladin`）里只建两个文件：

1. **`profile.py`**：职业常量，字段照 `guides/warrior-arms/profile.py` 写：
   - `CLASS`、`SPEC`：WCL 英文名。
   - `SPEC_ID`：天赋树专精编号。
   - `NAME`、`SPEC_LABEL`、`TREE_LABEL`、`EYEBROW`：中文名和各处标签。
   - `HERO`、`HERO_ENTRY`：英雄天赋中文名，以及它在天赋树 `subTreeNodes` 里 type=subtree 的 entry id。
   - `DEFAULT_CORE`、`DATE`。
   - `CLASS_ACCENT`：职业色，见 [writing.md](references/writing.md)「设计」。
   - `BIG_COOLDOWNS`：3–5 个大冷却（免疫、外部减伤、团队减伤这类），01 时间线画它们一整场交给了哪个机制。
   - `SKILLS`：本职业要上手册的技能 `{ID: (标签样式, 标签, 作用, 默认时机)}`，先只放确定会用到的，写手册时再补。
2. **`guides.py`**：开头写 `from guidelib import row, stop`，再写 `GUIDES = {}`，之后逐本往里加。

天赋树（`assets/talent-trees.json`）、设计样式、副本列表（`assets/season.json`）都是共用的，不要往职业目录里复制。测试 `tests/test_class_guides.py` 会自动检查所有有 `profile.py` 的目录。

## 流程：一次只做一本

每个副本走完下面 1–5 步再开下一本。不要先把八本的数据一起采完再统一写。

### 1. 采集
`collect.py <职业目录> <副本>`。脚本先统计前 20 场的英雄天赋，取多数；再挑三场同专精、同英雄天赋、不同玩家的最高层限时录像。如果提示与 `HERO_ENTRY` 不一致，改 `profile.py`。

### 2. 读证据表，挑行（核心）
跑 `evidence.py`，按 [references/method.md](references/method.md) 产出一张「技能 → 机制」候选表：
1. 逐个技能看「伴随」「直接效果」「给谁」「常接」，按分级标出必写和可写。
2. 每个候选机制查齐事实：谁施放、打谁、持续多久、伤害类型、能否驱散、有没有护盾或免控。证据表第三节有这些，缺的用 `--mechanic`、`--sql` 查。**这些事实就是「为什么」的原料。**
3. 03 专题要写时机的，用 `--mechanic` 量出时间差。
4. 最后补少量通用减伤行（团队爆发、叠层），不要每段都放。

### 3. 写内容
按 [references/writing.md](references/writing.md) 写 `guides.py` 里的一本。章节固定为：01 时间线 → 02 先学这四招 → 03 深挖专题 → 04 按路线逐段 → 05 工具箱 → 06 身上常中的减益 → 07 天赋。正文用到的技能要在 `profile.SKILLS` 里。

### 4. 天赋
推荐三名玩家之一的实际配置，它必须包含正文用到的全部天赋技能。`talent_cards` 放 6 张与本本相关的天赋树节点，不放基础技能。构建器会检查这一点并回验导入字符串；三套配置都不满足时会报错，这时要改正文，或换录像。

### 5. 构建与自查
- 先用 `build.py <职业目录> --dungeon <副本> --output-dir <scratchpad>` 预览，满意后去掉 `--output-dir`，加 `--png`。
- 用 Playwright 截 1100px 桌面和 390px 手机两张图，检查 02 卡片、03 专题、04 路线和天赋区。
- 跑测试：`python3 -m unittest discover -s tests`。
- 过一遍下面的清单。

## 治疗专精
治疗的职业技巧几乎都是「把哪个外部技能、哪次驱散交给谁」。证据表的「给谁」一列就是答案，写成角色：近战、坦克、被点名的人、血最低的人。自己的减伤和团队减伤只写在有具体伤害读条的地方；纯治疗量的技能（道标、治疗大招）不进路线。

## 交付前清单
- [ ] 盖住机制名，这本还能和别的副本互换吗？能互换就是模板，回到第 2 步。
- [ ] 证据表里的每条必写，要么进了正文，要么有不写的理由。
- [ ] 每条「为什么」至少有一个具体事实（数值、持续、施法者、打谁、能否驱散），且伤害类型和驱散类型与所按技能的效果对得上。
- [ ] 02 四招对应四个不同机制，都是本职业才有的处理，不是日常驱散，也不是单纯减伤。03 专题的时机数字是量出来的。
- [ ] 同一个技能全文前后一致：给谁、冷却、优先级都不矛盾，冷却与证据表对得上。
- [ ] 出声读一遍：像带过这本的队友在讲，而不是技能说明书（writing.md「语气」的对照表）；没有分号串参数、公文词和补丁句。每段都有一条讲取舍的提醒。
- [ ] 01 时间线的标签都讲得通，不对的用 `timeline_labels` 改掉。
- [ ] 证据弱的技巧（只有一名玩家这样做）措辞保守，不进 02。
