# 大秘境职业应对手册

手册是**攻略**，读者是要上场的玩家：看到什么 → 按什么 → 为什么。它的价值全部来自「高手在这本里额外做了什么」，不是通用减伤轮换。

上一轮战士手册质量低的原因就是反过来做：先排好路线骨架，再往每站填「反射接前段、姿态接后段」，录像里的嘲讽接反射、破裂投掷反而一条没写。**先从数据挑行，再补通用内容**，这是本 skill 唯一不能省的规则。

用户输入：$ARGUMENTS

## 工具

- 数据：`python3 <仓库>/.claude/skills/mplus-review/scripts/wcl.py`（下文 `wcl`），命令用法见 `mplus-tactics` skill。常用：`find`、`tactics`、`spell`、`pulls`、`points`。
- 施法者与连用：`python3 <本 skill>/scripts/mechanic_facts.py <副本源材料目录>`，列出每个敌方技能由哪种怪施放、该职业 5 秒内的技能连用，以及本职业每个技能的**最短施放间隔**和**给了谁**（职责·专精）。技能说明（`spells.json`）里没有冷却时间：正文写冷却、写「下一轮转没转好」时，以最短间隔为准，不凭记忆。它不输出敌方技能打谁，那个用 `wcl spell` 和原始事件的 `targetID` 查。
- 参考实现：`guides/warrior-arms/`（`guides.py` 内容源、`build.py` 构建器、`talents.py` 天赋编码、`research.py` 选录像与存分析、`prepare.py` 技能说明与图标）。**红玉新生法池那本是第二版样板**，其余七本是第一版，不要照抄第一版写法。
- 每小时 API 点数有限（全局 1000）。大批量拉取前先 `wcl points`；已保存的 `sources/<副本>/*.json` 优先复用。
- 只借用 `mplus-tactics` 的数据命令和判读方法；它的报告字段、字数限制和 `wcl render` 模板不适用于本 skill。
- 设计样式：直接复制 `guides/warrior-arms/sources/design.css`（`prepare.py` 从潜行者原稿重新提取它，新职业不必重跑这一步）。
- 天赋树：`guides/rogue/sources/dl/talents.json` 是 Raidbots 全职业天赋树快照，按 `specId` 取本专精（`prepare.py` 就是这么取的），存成 `sources/<专精>-tree.json`。

## 流程

### 1. 选三场录像
同专精、同英雄天赋、限时、层数最高的三场，三场来自不同场次、不同玩家；同层按用时排序。英雄天赋先定：查该副本排名前 20 个不同场次的天赋，取多数（`research.py` 默认不筛英雄天赋，要自己加；个别记录的 `combatantInfo` 是列表或缺天赋，记为未知，别让脚本崩）。新职业：复制 `research.py` 改职业/专精，存到 `guides/<职业-专精>/sources/<副本>/`（目录名用英文，如 `warrior-arms`、`holy-paladin`）（`<报告>-<场次>.md` 分析、`.json` 记录、`selected.json`）。

### 2. 从数据挑行（核心）
按 [references/row-selection.md](references/row-selection.md) 做，产出一张「机制 → 技能」候选表：
1. 从三份 `.md` 的「敌方机制 → 怎么应对」「按位置」「常连用」里抄出所有强关联。
2. 三场里 ≥2 场出现、或单场伴随倍数高（≥5 倍且 n≥3）、或有直接效果（驱散/反射/免疫/推断消除）的，**必写**。
3. 每个候选机制用 `wcl spell` 和 `mechanic_facts.py` 查清：谁施放、打谁（当前目标/一名玩家/全团）、持续多久、伤害类型、能否驱散、有没有护盾/免控。**这些事实就是「为什么」的原料。**
4. 再补少量通用减伤行（团队爆发、叠层），不要每站都放。

写正文前，把候选表给自己过一遍：录像里的每条强关联都在表里了吗？表里每条都有至少一个具体事实吗？

### 3. 写内容
按 [references/writing.md](references/writing.md) 的规则和字段写 `guides.py` 里的一本。章节固定为：01 时间线 → 02 先学这四招 → 03 深挖专题（`combo` 分步） → 04 按路线逐段 → 05 工具箱 → 06 身上常中的减益 → 07 天赋。

### 4. 天赋
推荐三名玩家之一的实际配置，**必须包含正文用到的天赋技能**（例如正文写破裂投掷，就不能推荐没点它的那套）。用 `guide['talent_cards']` 列与本本相关的 6 张卡，`talent_require` 由卡片自动推出。编码后解码回验。

### 5. 构建与自查
- 构建：`python3 guides/<职业-专精>/build.py --output-dir <scratchpad>`，满意后只把改动的那几本复制进 `guides/<职业-专精>/`（成品与源材料同目录）并导出 PNG（`wclr.export.export`）。
- 看图：用 Playwright 截 1100px 桌面和 390px 手机（`sips` 的裁剪偏移不可靠），检查 02 卡片、03 专题、04 路线、天赋区。
- 跑测试：`python3 -m unittest discover -s tests`。
- 过一遍下面的清单再交付。

## 治疗专精
治疗的职业技巧几乎都是「把哪个外部技能、哪次驱散交给谁」：自由、保护、牺牲、驱散的目标，录像里有，写成具体角色（近战、坦克、被点名的人、血最低的人）。自己的减伤和团队减伤只写在有具体伤害读条的地方；纯治疗量技能（道标、治疗大招）不进路线。自动分类会把治疗技能误归成「减伤」，按技能说明重判。

## 交付前清单
- [ ] 盖住机制名，这本还能和别的副本互换吗？能互换就是模板，回到第 2 步。
- [ ] 三份分析里的每条强关联，要么写进了正文，要么有理由不写（例如是种族技能、饰品、坦克专属）。
- [ ] 每条「为什么」都至少有一个具体事实（数值、持续时间、施法者、打谁、能否驱散）。
- [ ] 位移/控制技能都对应到具体机制；没有「飞跃躲正面」这种浪费冷却的建议。
- [ ] 一行写了几个技能，页面就显示几个；图标和说明一致。
- [ ] 03 专题讲的是这本最有特色的技巧，图示和标题说的是同一件事。
- [ ] 推荐天赋包含正文用到的全部天赋技能。
- [ ] 强调色是本职业的职业色（如武器战褐色 `#C69B6D`），成品 HTML 里搜不到盗贼金 `f2d24b` / `242,210,75`。见 `references/writing.md` 的「设计」。
- [ ] 没有证据类文字（「三名都这样打」「日志里 6 次」）、阵容、数据来源段落。
- [ ] 证据弱的技巧（只有一名玩家这样做，哪怕他做了很多次）措辞保守，或放进路线，不进 02 四招。
- [ ] 按 `references/writing.md` 的「简练」逐行过一遍：「为什么」超过 30 字的、带「但／仍要／别…／确认…」补丁的，删到只剩一个事实。
- [ ] 02 四招：四个不同机制；同一条连招最多一张；没有日常驱散（小怪叠层这类）；没有只靠团队减伤或个人减伤的卡（这些放路线）。每张都是给特定人的外部技能、免疫/自解、驱散关键减益、控制/破盾/改目标这类本职业才有的处理。
- [ ] 03 专题的时机数字来自候选表文件里算出的时间差，不是估的；「提前给」只出现在目标事先确定的机制上。
- [ ] 一致性：对每个出现过的本职业技能，把全文提到它的句子（路线、提醒、专题、工具箱、减益表）放在一起读一遍：给谁、冷却、优先级前后不矛盾；冷却数字和 `mechanic_facts.py` 的最短间隔对得上。
- [ ] 每条理由里的伤害类型、驱散类型和所按技能的效果对得上（物理免疫配物理伤害，驱散类型与减益一致）；同一事实全文前后一致。
- [ ] 分析里解释不通的直接效果（驱散/免疫）先查过修改该技能的天赋，没有直接判成误归因。
- [ ] 每段都有一条提醒，讲的是取舍（冷却留给谁、驱散先给谁、别的职业能替你做什么），不是复述行里的话。
