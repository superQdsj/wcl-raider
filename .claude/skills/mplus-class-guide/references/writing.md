# 写作规则与内容字段

## 语气：像带过这本的队友在讲，不是技能说明书
- 攻略不是报告：「信号 → 按什么（交给谁）→ 为什么」。中文，数字带单位：「6 秒」「20 码」「36 万火焰」。
- 不写证据和过程：「三名都这样打」「日志里 6 次」「没点这个天赋就没有…」，也不写阵容、数据来源段落。
- **写完整的短句，有主语、有因果。** 用句号分句，不要用分号、顿号把参数串成电报。
- **写按下去之后会怎样**，不要抄技能参数：写「流血当场没了」「他可以一直贴着打」，不写「移除流血效果」「免疫移动限制 8 秒」。
- **用玩家的说法**：交给、去掉、奶满、刷满、贴着打、反回去、砸盾。不用公文词：可被、覆盖、处理、进行、有效、需、予以。
- 数字只留读者要用的那一个，放在句子里。

| 生硬（不要） | 自然（要） |
|---|---|
| 只打当前目标；反射首个法术。 | 火热冲击只打坦克。先嘲讽，它就朝你读，读条时开反射还回去。 |
| 护盾在时脉冲；破裂投掷对护盾 +500%。 | 冰盾在的时候每 1.5 秒全队掉血。破裂投掷砸盾多打五倍，盾一出就丢。 |
| 7 秒引导可被昏迷打断。 | 引导 7 秒，每秒 6.5 万。一锤晕住就断了。 |
| 死亡 20 码爆炸需规避。 | 它死的时候 20 码内吃 48 万火焰，近战提前跳出去。 |

## 长度（读者在战斗间隙扫一眼）
- **路线行「为什么」**：一两句，一般 15–35 字，最多 60 字。短靠删掉多余的事实，不靠删主语和连接词。
- **02 卡片（`row(..., card=...)`）**：两句，30–70 字。第一句说按了之后会怎样，第二句补最关键的一个事实或例外。卡片和路线行写同一件事，但卡片要能单独读懂。
- **不打补丁。** 「但首发仍要抬血」「别等残血才救」「可尝试晕住」这类附加条件和含糊措辞，要么删掉，要么（真的重要时）挪到本段提醒里说一次。证据不够硬就不写这一行，不要用「可尝试」兜底。
- **信号只写看到的东西**，6–12 字：「首领套上寒冰壁垒」「喷吐点到自己」「痛击叠到 3 层」。不写判断（「流血难抬」「叠层危险」），也不写「队伍血线下降」这种每个读条都成立的话。
- **同一个机制、不同处理，拆成两行**，用信号区分条件：「点到自己 → 个人减伤」和「点到队友 → 外部减伤给他」是两行。只有真正同时按的技能才放进同一行，页面会显示「+」。
- **交给谁写职责**：坦克 / 近战 / 被点名的人 / 血最低的人 / 自己。不写录像里的具体职业，也不写「提前约定给谁」。
- **不写空泛的保命行**：「无路可走时开免疫」不是技巧。免疫和长冷却只留给有名字的伤害读条。

## 每段提醒（`stop` 的第 4 个参数，必填，≤40 字）
每段一句，讲**取舍**，不要复述行里已经写过的话。可以讲：
- 冷却留给谁；
- 几个目标抢同一个驱散或外部技能时先给谁；
- 减益的结束条件能替代技能时，写出来；
- 别的职业能替你做什么；
- 哪两个机制叠在一起最容易减员。

例：「反射还在冷却就别嘲讽，这一发交给打断轮」。

## 页头导语（`lede`）
三四句话，像开打前跟队友交代：第一句说这本到处是什么（读条、护盾、流血、定身……），然后用 `<b>` 点出 2–3 个关键技巧，每个写成「看到什么 → 把什么交给谁」，最后可以补一句小怪段的主要工作。

## 01 时间线
自动画出推荐玩家那一整场里大冷却（`profile.BIG_COOLDOWNS`，单本可用 `timeline_skills` 改）的每一次使用，标签是当时在应对的机制。构建后看一眼：标签不对的用 `timeline_labels={'4:48': '冰霜过载 · 第一轮'}` 改（起始时间取页面上显示的），不想要的点设为 None。超过 `timeline_max`（默认 12）个点时会均匀抽样，重要的点被抽掉时，先用 None 去掉赶路之类的无关点。

## 02 先学这四招（`moments`）
- 四个不同机制、四种不同的按钮用法。同一条连招最多占一张卡。
- 留给「按错就减员」的时刻：外部技能给特定的人、免疫或自解、驱散关键减益、控制、破盾、改目标。
- 日常驱散（小怪叠层）和单纯的团队或个人减伤放进路线，不占四招。

## 03 专题（`combo`）
- 只讲一个技巧：本本最有特色、最需要步骤说明的那个。
- `steps` 里的时机用 `evidence.py --mechanic` 量出的「每场中位」，写成窄范围，并写清起点是读条开始还是落地（如「火热冲击读条开始后 2–4 秒」）。不要把全部样本的最小–最大值当范围。
- `outro` 写边界或替代用法。

## 06 减益表
- 只放减益，不放增益。
- 处理不了的也要列，写「✗ 只能减伤」「✗ 刷满就掉」，让读者知道哪些不用浪费驱散。
- 「能自解吗」只写本职业真正能用、也值得用的技能。免疫/清除技能只写在值得交它的减益上（流血、叠层、定身）；全团持续伤、点名燃烧这类，即使免疫技能技术上能清，也写「✗ 只能减伤」「✗ 只能分担」。站在里面才掉血的区域，不能写成「可以免疫清除」。

## 设计
样式是 `assets/design.css`（潜行者原稿：深色、单一强调色，字体为 Noto Serif SC / Noto Sans SC / JetBrains Mono），构建器负责加组件和内嵌图标。强调色在原稿里写死为盗贼金，构建时会按 `profile.CLASS_ACCENT` 换成本职业色。`--gold-dim` 取职业色压暗约 40%，`rgba(...)` 用职业色的 RGB：

| 职业 | 色值 | 职业 | 色值 |
| --- | --- | --- | --- |
| 战士 | `#C69B6D` | 圣骑士 | `#F48CBA` |
| 猎人 | `#AAD372` | 潜行者 | `#FFF468` |
| 牧师 | `#FFFFFF` | 死亡骑士 | `#C41E3A` |
| 萨满祭司 | `#0070DD` | 法师 | `#3FC7EB` |
| 术士 | `#8788EE` | 武僧 | `#00FF98` |
| 德鲁伊 | `#FF7C0A` | 恶魔猎手 | `#A330C9` |
| 唤魔师 | `#33937F` | | |

太亮的颜色可以略压饱和度，保证按钮上的深色文字还能看清；太暗的可以略提亮。

## guides.py 字段（样板：`guides/warrior-arms/guides.py` 红玉新生法池）

```python
'副本名': {
    'theme': '目录页一句话主题（≤16 字）',
    'core': '页头「核心」：本本最重要的 2–3 个按钮',
    'lede': '页头导语，<b> 标出 2–3 个关键技巧',
    'combo': {                      # 03 深挖专题
        'title': '技能 → 技能：一句话讲清目的',
        'skills': [355, 23920],     # 标题里的技能
        'intro': '为什么能这样做（机制事实）',
        'steps': ['第 1 步…', '…'],  # 3–5 步，可用 <b>
        'outro': '配合与边界',
        'cap': '示意图说明',
        'tracks': [(名称, 图标ID, 图标位置%, 线起点%, 线宽%, 右侧标注), ...],
        'result': ['效果1', '效果2', '效果3'],
    },
    'route': [
        stop('段名', 'trash' | 'boss', [
            row('机制名', '信号', [技能ID, ...], '为什么（含事实）',
                tags=[('火焰', 'fire'), ('6 秒', '')], who='交给谁',
                mechanic_id=None,           # 同名机制有小怪版/首领版时，显式给技能 ID
                card=None),                 # 进 02 时卡片上的两句话
        ], '本段提醒'),
    ],
    'moments': [(段序号, 行序号) × 4],
    'debuffs': [(名称, 类型, 能自解吗, 怎么处理[, 技能ID]), ...],  # 「否」以外的值显示为绿色
    'timeline_skills': [技能ID, ...],    # 可选：01 时间线追踪的大冷却，默认 profile.BIG_COOLDOWNS
    'timeline_labels': {'m:ss': 标签},   # 可选：改某个点的标签，None 去掉
    'tools': [技能ID, ...],              # 05 工具箱，只放本本用到的，6–8 个
    'tool_stars': [技能ID, ...],         # 高亮
    'tool_notes': {ID: (作用, 本本时机)}, # 可选，覆盖 profile.SKILLS 里的默认说明
    'talent_cards': [(ID, 说明), ...],   # 6 张天赋树节点；改变技能效果的天赋优先
    'talent_keys': [ID, ...],            # 高亮的天赋卡
}
```

- `mechanic` 和减益名必须是录像里出现过的敌方技能名，构建器按名字在本副本里找 ID。同名机制有小怪版和首领版时，行里写清是哪一版，需要时显式给 `mechanic_id`。
- `tags` 的 kind 取 `fire` `frost` `nature` `magic` `poison` `bleed`，或空字符串。
- 段落：首领战用首领名；小怪段写「A → B」。一段 2–5 行；没有职业技巧的段可以只有 1 行。
