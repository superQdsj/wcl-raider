# 写作规则与内容字段

## 语气（用户明确要求）
- 攻略不是报告：「信号 → 按什么（交给谁）→ 为什么」。
- 不写证据和过程：「三名都这样打」「日志里 6 次全部命中」「没点这个天赋就没有…」、阵容、数据来源段落都不要。
- 中文。数字带单位：「6 秒」「20 码」「36 万火焰」。
- 每句「为什么」至少一个具体事实。

## 简练（审稿最常打回的地方）
读者在战斗间隙扫一眼，一行只留**一个最关键的事实**。

- **「为什么」一般 10–25 字，超过 30 字就要砍。** 例：「7 秒引导，每秒 6.5 万；一晕就断」「只打当前目标，嘲讽后反射」。
- **不打补丁。** 「但首发自然伤仍要抬血」「减伤期间仍要选好落点」「确认开着某光环」「别只顾赶路」「不要等残血才开」这类附加条件、劝诫，要么删掉，要么（真的重要时）挪到本段提醒里说一次。
- **信号只写看到的东西**，6–12 字：「首领套上寒冰壁垒」「引导者电击一名队友」「喷吐点到自己」。不写「队伍血线下降」这种每个读条都成立的话。
- **同一个机制、不同处理，拆成两行，用信号区分条件**，不要在一格里写「A 或 B」：
  - 「点名 · 点到自己 → 个人减伤」和「点名 · 点到队友 → 外部减伤给他」是两行；
  - 「火焰风暴全队烈火 → 反射」和「层数叠高、反射在冷却 → 剑在人在」是两行（红玉新生法池·柯姬雅）。
  - 只有真正同时按的才放进同一行（「牺牲 + 圣盾」），页面显示「+」。
- **交给谁要具体到角色**：坦克 / 近战 / 被点名的人 / 血最低的人 / 自己。写职责，不写录像里的具体职业（「给近战」，不是「给潜行者、死亡骑士」）。不写「提前约定给谁」「给需要保持行动的队友」——录像里这个技能给了谁，就写那类人。
- **不写空泛的保命行。** 「无路可走时开免疫」「叠群伤时开减伤」不是技巧；走路能躲、或任何一本都成立的，删掉。免疫和长冷却留给有名字的伤害读条。

## 每段提醒（`stop` 的第 4 个参数）
每段都要有，一句话讲**取舍**，这是区分高手与新手的地方：
- 冷却留给谁：哪个大读条有固定间隔，减伤别随手交，留给它；
- 驱散/外部/打断给谁优先：几个目标抢同一个冷却时先给谁，为什么；
- 不用技能的解法：减益的结束条件（回满血、离开区域、打掉某物）能替代技能时写出来；
- 别的职业能替你做什么：队里有某职业时把这件事交给他，自己的冷却留给别处；
- 最容易减员的时刻：哪两个机制叠在一起最危险，大冷却别提前交掉。
例（红玉新生法池·武器战）：「反射还在冷却就别嘲讽，这一发交给打断轮」。
不要复述行里已经写过的话。

## 页头导语（`lede`）
第一句用一个短语概括这本对本职业意味着什么（伤害和减益的主基调：哪种系别、定身/流血/读条多不多），然后用 `<b>` 点出 2–3 个关键技巧，每个技巧写成「机制 → 按什么给谁」。三句以内。

## 03 专题
- `steps` 里的时机要**从录像量出来**并写成数字（三场里本职业技能相对机制的时间差，算好写进候选表文件，再取范围）：例如「嘲讽后 2–4 秒」，不写「读条后半段或刚结束」这种含糊说法。
- 交给谁同样具体到角色，并写出天赋带来的附加效果（例如某天赋让自己也同时获得效果）。
- `outro` 写边界或替代用法（例如「嘲讽前跟坦克说一声，6 秒后仇恨自己回去」）。

## 06 减益表
- 只放**减益**，不放增益（自己叠的增伤 buff 不是减益）。
- 不能处理的也要列，写「✗ 只能减伤」「✗ 只能分担」「✗ 刷满就掉」，读者需要知道哪些别浪费驱散。
- 「能自解吗」写本职业真正能用的技能；一个持续伤害区域（站在里面才掉血）不能写成「可以免疫清除」。

## 设计
沿用 `guides/rogue` 的设计系统（`sources/design.css`）：深色、单一强调色、Noto Serif SC / Noto Sans SC / JetBrains Mono，图标全部内嵌。不要用 `wcl render` 模板。

**强调色必须是本职业的职业色。** `design.css` 是潜行者原稿，强调色写死为盗贼金（`--gold:#f2d24b`、`--gold-dim:#8a7a2c`、`rgba(242,210,75,…)`），直接沿用会让别的职业手册通篇是盗贼金。`build.py` 的 `CLASS_ACCENT` 在构建时把这几个值整体替换成本职业色（变量名 `--gold` 保留不改，只换值）；新职业复制构建器后先改这张表。`--gold-dim` 取职业色压暗约 40%，`rgba(...)` 用职业色的 RGB。暴雪官方职业色：

| 职业 | 色值 | 职业 | 色值 |
| --- | --- | --- | --- |
| 战士 | `#C69B6D`（褐） | 圣骑士 | `#F48CBA` |
| 猎人 | `#AAD372` | 潜行者 | `#FFF468` |
| 牧师 | `#FFFFFF` | 死亡骑士 | `#C41E3A` |
| 萨满祭司 | `#0070DD` | 法师 | `#3FC7EB` |
| 术士 | `#8788EE` | 武僧 | `#00FF98` |
| 德鲁伊 | `#FF7C0A` | 恶魔猎手 | `#A330C9` |
| 唤魔师 | `#33937F` | | |

太亮的（牧师白、武僧绿、潜行者黄）可略压饱和度，保证按钮上的深色文字（`#17140a`）仍可读；太暗的（萨满蓝、死骑红）可略提亮，保证在深色底上的正文强调可读。

## guides.py 字段（第二版，以红玉新生法池为准）

```python
'副本名': {
    'theme': '目录页一句话主题（≤16 字）',
    'core': '页头「核心」标签：本本最重要的 2–3 个按钮',
    'lede': '页头导语，<b> 标出 2–3 个关键技巧',
    'combo': {                      # 03 深挖专题
        'title': '技能 → 技能：一句话讲清目的',
        'skills': [355, 23920],     # 标题里的技能
        'intro': '为什么能这样做（机制事实）',
        'steps': ['第 1 步…', '…'],  # 3–5 步，可用 <b>
        'outro': '配合与边界',
        'cap': '示意图说明',
        'tracks': [(名称, 图标ID, 图标位置%, 线起点%, 线宽%, 右侧标注), ...],
        'result': ['效果1', '效果2', '效果3'],
    },
    'route': [
        stop('段名', 'trash' | 'boss', [
            row('机制名', '信号：谁在做什么', [技能ID, ...], '为什么（含事实）',
                tags=[('火焰', 'fire'), ('6 秒', '')], who='交给谁/丢谁'),
        ], '可选：本段一条提醒'),
    ],
    'moments': [(段序号, 行序号) × 4],   # 02 先学这四招：本本最有特色的四条
    'debuffs': [(名称, 类型, 能自解吗, 怎么处理), ...],  # 「否」以外的值显示为绿色
    'tools': [技能ID, ...],              # 05 工具箱，只放本本用到的，6–8 个
    'tool_stars': [技能ID, ...],         # 高亮
    'tool_notes': {ID: (作用, 本本时机)}, # 覆盖通用说明
    'talent_cards': [(ID, 说明), ...],   # 6 张天赋树节点（基础技能不放），必须都在推荐配置里；改变技能效果的天赋（多驱散一种类型、外部技能附带清除）优先
    'talent_keys': [ID, ...],            # 高亮的天赋卡
}
```

- `mechanic` 必须是录像里出现过的敌方技能名；构建前用 `prepare.py` 的逻辑重生 `mechanics.json`，并确保 `spells.json` 里有每个 ID 的说明和图标（缺的用 `wclr.wowhead.spells` 补，图标从 zamimg 下载）。
- `tags` 的 kind：`fire` `frost` `nature` `magic` `poison` `bleed` 或空字符串。
- 段落：首领战按首领名；小怪段写「A → B」。一段 2–5 行（机制多的首领可到 5 行，拆条件行不算浪费），没有职业技巧的段可以只有 1 行。
- `moments` 选四个不同机制、四个不同的按钮用法，优先选组合技和破盾/控制/免疫这类职业特色，不选通用减伤。
  - 同一条连招（例如 03 专题的前后两步）在 02 里最多占一张卡。
  - 日常驱散（小怪叠层、每波都要清的减益）和单纯的团队/个人减伤放路线，不占四招；四招留给「按错就减员」的时刻：大流血、叠层自解、破盾、改目标。
- 同名机制有小怪版和首领版（持续、伤害不同）时，行里写清是哪一版，事实别混用；构建器按名字找技能 ID，可能链到另一版，需要时在行里显式给 ID。
- 03 专题只讲一个技巧，选本本最有特色、最需要步骤说明的那个。
