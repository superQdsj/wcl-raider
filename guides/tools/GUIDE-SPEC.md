# 职业副本手册：样板规范

> 唯一参考样板：`guides/rogue/sources/duya-sample/`（源码：`head.part`、`body.part`、`build.py`、`NOTES.md`；生成物：`sample.html`）。
> 核心原则：**一条路线讲到底，每条知识只说一次；顶部做速查入口，视觉沿用各职业主题；固定阅读顺序，允许职责决定内容。**

本规范适用于所有职业与专精（DPS、保人型 DPS、治疗、坦克），服务两个阅读场景：
1. **开打前看 5 分钟**：读页头一句话 → 扫速记区核心牌与硬限制 → 看单轨时间轴建立整场冷却节奏。
2. **打本时瞄第二屏**：用吸顶阶段导航或高频职责清单直跳当前波次，扫带「必做」标签的高亮行确认动作。

## 一、板块顺序与职责（固定 5 块）

页面从上到下固定以下 5 块，**不再单设「先学四招」「工具箱」「减益表」「首领独立专题」**，杜绝同一条知识反复复述。

| 顺序 | 板块 | 锚点 | 职责 | 不该放什么 |
| --- | --- | --- | --- | --- |
| 0 | 页头 + 吸顶导航 | — | 一句话建立整本主思路；提供各段锚点跳转 | 营销口号、筛选/高亮交互按钮 |
| 00 | 开打前速记 | `#prep` | 3–4 张核心牌定位 + 1 条职业硬限制（有则写）+ 全本高频职责清单（可选） | 展开具体首领机制轴（留给路线） |
| 01 | 单轨时间轴 | `#timeline` | 选 1 场代表录像，直观展示关键大招交在哪些时间点 | 多名玩家并排多轨图、本地分叉 `timeline.py` |
| 02 | 按路线逐段 | `#route` | **唯一的知识正文**：按推进顺序写清「看到什么 → 按什么 → 为什么」 | 样本数、单场统计次数、灰色数据小字 |
| 03 | 天赋与页尾 | `#talent` | 可导入的天赋字符串 + 关键防御/功能天赋 + 页尾参考录像 | 展开纯输出天赋、在正文提参考玩家名 |

### 各板块细则

1. **页头与吸顶导航**
   - 必须保留 `<p class="lede">...</p>`（`scripts/build_site.py` 会提取它作为首页摘要），且 `<body>` **严禁添加任何属性**（`build_site.py` 靠字面匹配 `"<body>"` 注入右上角 `← 全部手册`）。
   - 导语 2–3 句讲清本副本核心伤害/机制特点、主大招节奏与最大例外，用词与正文冷却逻辑保持一致（不把隔轮才转好的技能写成每轮必开）。
   - 吸顶导航（`.nav`）：放 `速记 | 时间轴 | 路线各段 | 天赋`。路线各段用短名与首领序号（如 `开场 / ①拉维 / 进化者 / ②盘蛇`），**不与板块编号 `00–03` 撞号**。只做锚点跳转和轻量滚动高亮（含滚到底部时高亮「天赋」的兜底），**不做筛选和高亮交互**。外层 `.nav .wrap` 固定留出 `padding-right: 124px`，内层 `.nav-scroll` 在剩余宽度内横向滚动，确保溢出链接不会滑到发布版 `← 全部手册` 下方。

2. **00 开打前速记（`#prep`）**
   - **核心技能（3–4 张卡，`.cores` 用 `auto-fit` 网格自适应 3 或 4 张）**：写「图标 + 技能名 + 冷却/充能/持续时长 + 1–2 句职责定位」。定位可点一句 3–5 字适用场景，**不展开具体首领步骤**，且措辞不能夸大技能边界（如不可把部分毒清不掉的技能写成清除一切毒）。
   - **职业硬限制（可选，至多 1 条）**：只写「新打这个本最容易按错或误判致死」的**机制铁律**（如圣骑士 30 秒自律、潜行者斗篷不挡物理且清不掉仪式毒液/感染、治疗单驱散 8 秒 CD 的双点名优先级）。不要把通用常识硬凑成硬限制；没有真硬限制就省略此块。
   - **全本高频职责清单（可选，按职责命名）**：默认 2–5 张卡片（`.kicks` 用 `gap:1px` 网格线，任意张数折行均闭合），点击直跳路线对应行（`id="k-..."`，配合中性色 `:target` 定位）。具体怎么选见第三节。

3. **01 单轨时间轴（`#timeline`）**
   - 必须复用共享 `guides/tools/timeline.py`（注入 `GOLD_TL_CSS` 与 `timeline(...)`），**严禁在源码目录复制分叉或打本地 CSS 补丁**。图例直接使用共享样式 `.legend i.pri / .e / .v / .muted / .boss / .trash`。
   - 选 1 场代表性录像画单轨，常规建议标 **6–14 个点**，单条标签 **≤ 8 字**（短 CD 职业允许稀疏取样，只标关键高压覆盖窗口；合波集中交多张大招的治疗/坦克可将同窗口施法合并为单点并用 4–5 字短标签，避免同侧标签重叠）。
   - 标记按**技能类别**着色：`''` = 主大招（`--gold`），`'e'` = 副手牌 1（`--tl-e`），`'v'` = 副手牌 2（`--tl-v`），`'muted'` = 顺手/可选（灰）。
   - 时间轴是**单场实录**，图注须说明「展示真实冷却节奏，非每波强制照搬」；时间轴上每个主色点都应能在路线里找到说明，但**不要求与路线「必做行」一一对应**（必做行也可能是副手牌或短 CD 动作）。

4. **02 按路线逐段（`#route`）**
   - 按实际推进顺序分 **小怪（`.trash`）** 与 **首领（`.boss`）**，每张卡三层结构：
     1. **段头 + 节奏栏**：段头标全本段正文涉及的关键小怪名单或首领编号；紧跟一句「节奏」（高压波次用 `.rhythm.warn`），写清**冷却取舍条件**（如「距下一个必留点 ≥ 2 分钟才交 + 未转好时的备选」），不写死依赖特定拉怪速度的「正好转好」。
     2. **机制行**：默认三列 `看到什么 → 按什么 → 为什么`。路线副标题用颜色无关的描述（「带「必做」标签的高亮行」），不要写死「金色」。
        - **必做行（`.row.must`）**：默认 **3–6 行**（按实际副本复杂度增减），用职业主强调色左边框 + 浅底色 + `必做` 徽章标出。
        - **复杂首领机制**：不单开专题板块，直接并入该首领卡片，用**时间步骤行**（`.row.step`，第一列 `minmax(72px,auto)`，明确每个时间的起算点，如「0 秒开始读条 / 约 +5 秒生效 / +32 秒切骨者读条 / 看减益倒计时」）讲清一轮流程；仅在跨场稳定的对比数字能直接解释「为什么这样按」时附 1 组对比条（单场数据不进对比条）。
        - **跨段重复小怪**：首次出现写全机制细节，后段再次遇到时简写为「同前段」并只补充新叠加互动，避免整段复制。
     3. **段尾栏**：左侧写建议节奏与条件（如「建议：斗篷 1–2 次」「切骨者每轮交佯攻，闪避隔轮叠」，**只写建议节奏，不写单场统计次数**；如某段无关键大招分配可写核心注意点或省略左侧），右侧放下一段跳转锚点。
   - **删除旧板块前的信息守恒**：不写工具箱和减益表，但所有独有细节（驱散类型、应急副解、结束炸裂/爆小怪、治疗吸收盾、免疫无效的物理伤害、精准按键时机）必须全部落进对应路线行。

5. **03 天赋与页尾（`#talent` + `footer`）**
   - 天赋字符串编码并反向解码核对 `0 不一致`，配一键复制按钮；若 5 场报告均无 WCL 天赋记录，省略导入栏并在 `NOTES.md` 说明原因，仅保留关键天赋文字卡片（`build.py` 只在模板含 `{{TALENT}}` 时读取 `tstring.json`，前端复制脚本须判空 `if(btn && code)`，避免无导入栏时中断构建或导航滚动高亮）。
   - 只列 **3–4 个不要动的防御/功能关键天赋**（纯输出天赋不展开），常见可替换天赋用一句话说明。
   - 参考录像链接只放页尾 `<footer>`。

## 二、内容、视觉与工程硬规则

### 内容与分层取证硬规则
- **写攻略，不写统计报告**：正文不出现参考玩家名，不写 `5/5 人`、`五场`、`中位数`、`共 N 次`、`全场最多/最重`、`平均` 等统计报告措辞。
- **数字准入**：只用在两处——① 技能精确窗口（冷却、充能、持续、读条秒数、码数，须在 `NOTES.md` 标明来源）；② 直接解释「为什么这样按」的跨场幅度（如「少吃四成」「几乎砍半」「不开吃将近 90 万」或跨场对比条）。
- **分层取证门槛与补查方法**（结合 `guides/tools/evidence.py` 的实际边界）：
  - `evidence.py` 目前只采集本玩家施法、个人与全队承伤、本玩家减益与防御增益窗口，**不采集治疗/吸收事件、对队友施加的目标增益或坦克主动减伤覆盖**。按结论层级取证：
  1. **机制事实**（伤害属性、读条时长、驱散类型、免疫判定）：以 `spells.md` + `compare.md` / `debuffs.md` 为准，绝不望文生义。
  2. **常规推荐打法**：多数样本一致（≥ 3/5）且有对应窗口/效果对比；仅 1–2 人做的常规打法直接删，记入 `NOTES.md` 的「删掉的低样本打法」，不进正文推荐或对比条。
  3. **应急兜底 / 备选打法**：允许低样本或由机制事实支撑（如漏接两把飞斧后斗篷顶喷发、血线危急时兜底交牌），但正文必须明标「兜底 / 备选」，不得写成常规主轴或混入主轴时间轴。
  4. **保人 / 治疗 / 坦克定向补查**（每次必带 `--ability` 与 `--from/--to`；注意 `wclr/cmd_events.py` 过滤语义：`--type healing / buffs` 传 `--player X` 时按**承受者** `target.name` 过滤，按施法者过滤必须用 `--filter 'source.name = "..."'`，若只看特定队友再配合 `--target "<队友>"`）：
     - **保人核对（施法 → 目标增益 → 目标承伤）**：先从 `uses.md` 找到对队友的施法时间，再分别查目标身上的保人增益 ID 与敌方伤害 ID：
       ```sh
       python3 guides/tools/wcl.py events "<WCL链接#fight=N>" --type buffs --target "<队友>" --ability <保人增益ID> --filter 'source.name = "<本玩家>"' --from m:ss --to m:ss
       python3 guides/tools/wcl.py events "<WCL链接#fight=N>" --type damage-taken --player "<队友>" --ability <敌方技能ID> --from m:ss --to m:ss
       ```
     - **治疗核对（有效治疗 / 吸收 → 目标）**：
       ```sh
       python3 guides/tools/wcl.py events "<WCL链接#fight=N>" --type healing --ability <治疗或吸收技能ID> --filter 'source.name = "<治疗者>"' --from m:ss --to m:ss
       ```
     - **坦克核对（尖刺命中 → 主动减伤覆盖）**：先在 `classes/<坦克>.json` 补齐主动减伤增益 ID 重跑 `evidence.py`，或同时查主动减伤增益 ID 与敌方尖刺技能 ID 对照：
       ```sh
       python3 guides/tools/wcl.py events "<WCL链接#fight=N>" --type buffs --player "<坦克>" --ability <主动减伤增益ID> --from m:ss --to m:ss
       python3 guides/tools/wcl.py events "<WCL链接#fight=N>" --type damage-taken --player "<坦克>" --ability <敌方尖刺技能ID> --from m:ss --to m:ss
       ```

### 视觉硬规则
- **路线内主强调色只说一件事**：路线正文（`#route`）内，主强调色（`--gold`）**严格只留给必做行的 5 个选择器**：`.row.must`、`.badge-must`、`.row.must .to`、`.row.step.must .when`、`.row.must .btn-chip.pri`。普通首领节点、节奏标签、下一段链接、`:target` 定位与承伤对比条（含免疫项）一律用中性色；禁止堆叠多种颜色的机制/效果药丸（`.pill` / `.tag.magic` 等）。
- **彻底变量化，单点换肤**：`head.part` 与 `body.part` 在 `:root` 之外**不得出现任何硬编码色值或 rgba**（仅允许对比条柱宽 `style="width:..."`）。`:root` 必须声明完整色板变量：
  `--bg`、`--nav-bg`、`--panel`、`--panel-2`、`--line`、`--line-2`、`--tint-1`、`--tint-2`、`--ic-edge`、`--ink`、`--ink-2`、`--mute`、`--faint`、`--gold`、`--gold-dim`、`--on-gold`、`--gold-bg`、`--gold-chip`、`--gold-band`、`--hero-a`、`--hero-b`、`--tl-e`、`--tl-v`、`--bar-off`、`--bar-mid`、`--on-bar`、`--blood`、`--blood-bg`、`--blood-line`。
  > 兼容例外：共享 `guides/tools/timeline.py` 中的回退值（`rgba(242,210,75,.12)`、`--nature`、`--shadow`、`#000`）仅用于兼容未迁移旧页；新页声明完整 `:root` 后会全部覆盖，且使用 `--tl-e`/`--tl-v` 避开与 `--shadow`（阴影）冲突。
- **禁止外部资源 CDN**：不引入 Google Fonts 或任何外部 CSS/JS；统一使用纯系统字体栈。页尾 WCL 录像超链接属于外部参考链接，不受此限。
- **对比度底线**：所有可读文字（含辅助说明、段尾栏、主色按钮 `--on-gold`、对比条 `--on-bar`）与底色对比度 ≥ 4.5:1（WCAG AA）。

### 工程、天赋编码与发布硬规则
- **源码目录与共享输入**：正式新攻略放在 `guides/<职业目录>/sources/<副本拼音>-v2/`，必备 `head.part`、`body.part`、`build.py`、`NOTES.md`。正式副本把 `evidence/`、`tstring.json`、`icons.json` 放本目录（`DATA_DIR = H`）；若如样板（`duya-sample`）或二次改版（`zhuwang-v2`）复用兄弟目录数据，须在 `build.py` 显式写明 `DATA_DIR` 并在 `NOTES.md` 记录路径。
- **天赋编码流程（含新专精）**：从 `evidence/talents.json` 选一名层数高/用时短且具备 `talentTree` 的玩家导出为 `talents_raw.json`，准备对应专精的 Raidbots 节点树 `talents.json`（按目标 `specId` 过滤，参照 `guides/rogue/sources/duya-v2/enc.py` 修改 `specId` 与输入路径），运行编码并用 `decode()` 校验 `0 mismatch / 0 extra` 生成 `tstring.json`。若 5 场均无天赋记录，省略导入栏并在 `NOTES.md` 注明。
- **离线重建与外链图标**：`build.py` 复用共享 `guides/tools/timeline.py` 和 `guides/tools/icons.py` 的 `externalize(out)`，支持可选输出路径 `python3 build.py [out.html]`，断言无 `{{` 残留；成品不内嵌 base64。
- **站点发布契约（`scripts/build_site.py`）**：
  1. 成品输出路径必须为 `guides/<职业目录>/YYYY-MM-DD-<副本中文名>-<职业>.html`（`build_site.py` 按 `-` 分段，从第 4 段起匹配 `DUNGEON_INFO` 副本中文名，命名不符会被静默跳过）；
  2. 保持裸 `<body>` 与 `<p class="lede">`；
  3. 新增职业/专精目录（例如坦克）须同时登记到 `scripts/build_site.py` 的 `CLASSES` 字典，并在 `site/img/icons/<icon>.jpg` 放好对应专精图标文件。
- **只交付 HTML**：不出 PNG 长图，不做截图检查，不管手机宽度专项适配。
- **`NOTES.md` 四项必备**：① 5 场录像来源、数据目录与仓库根目录可执行的重建命令；② 技能基础窗口与每条核心结论的量化证据（含位移/低频技能来源）；③ 删掉的低样本打法；④ 天赋 0 差异核对与 `wcl.py` 补查记录。

## 三、新职业套用指南

套用新职业时，**五块结构、组件代码与硬规则保持不变**，只调整 `:root` 配色与各板块的职责内容：

### 1. 配色主题（只改 `:root`）
- **已有 v2 源码的职业**：沿用该职业标准暗底 v2 `head.part` 的配色——已核实：
  - `rogue`：潜行者金 `#f2d24b` 配副本暗底（如毒林夜色 `#0d1210`）；
  - `paladin-ret`：统一沿用 `duya-v2` / `mimou-v2` 的圣骑士粉 `#f39cc3` 配 `#100e0d`（不沿用 `zhuwang-v2` 的旧金色试验稿 `#d9ab52`）；
  - `demonhunter-devourer`：恶魔猎手紫 `#c77ae6` 配 `#100e0d`。
- **暂无标准 v2 源码或新增职业**（如 `warrior-arms`、`holy-paladin`、坦克等）：以 `scripts/build_site.py` 的 `CLASSES` 职业色为基准，调出暗底对比度 ≥ 4.5:1 的 `--gold`、`--gold-dim` 与对应 `--on-gold`（亮强调色配深字如 `#17140a`，深强调色配浅字如 `#f5f5f5`）。

### 2. 四类角色适配矩阵

| 角色类型 | 速记 3–4 格怎么选 | 顶部高频职责清单（可选） | 时间轴怎么画 | 路线正文重点与动作写法 |
| --- | --- | --- | --- | --- |
| **免疫/大招 DPS**<br>（潜行者、法师、猎人等） | 免疫/硬解 → 常驻减伤 → 副减伤 → 自疗/功能 | **全本必断读条**（有短打断且 ≥ 2 个关键读条时保留） | 标 1.5–3 分钟免疫与核心减伤点（6–14 点） | 写清免疫能/不能挡什么、顺手交牌的冷却余量与未转好时的备选 |
| **短 CD / 无免疫 DPS**<br>（武器战、噬灭 DH 等） | 主减伤 → 副减伤/吸血 → 群控/打断 → 关键位移 | **全本必断读条**或**关键群控点** | 允许稀疏取样，只标关键高压覆盖窗口或 1.5 分钟以上大减伤 | 区分「单波致死需叠减伤」与「连波持续伤需错峰覆盖」；远程写清射程、站位与打断分工 |

| **坦克** | 常驻主动减伤 → 大减伤牌 → 魔法/特殊应对 → 位移/风筝或群控 | **全本必断 / 关键群控点** | 标 1.5–3 分钟大减伤与无敌/春哥等兜底牌；同波叠牌合并短标签 | 聚焦**尖刺死刑技覆盖、合波起手减伤衔接、带位与风筝退出条件**；段头节奏写清起手和合波大招分配 |
