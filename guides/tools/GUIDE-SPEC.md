# DPS 职业副本手册：制作规范

> 唯一参考样板：`guides/rogue/sources/duya-sample/`（源码：`head.part`、`body.part`、`build.py`、`NOTES.md`；生成物：`sample.html`）。
> 核心原则：**只服务 DPS 专精；一条路线讲到底，每条知识只说一次；顶部做速查入口，视觉沿用各职业主题；机械规则交给 `check.py`，逻辑质量交给 6 问自检。**

服务两个真实阅读场景：
1. **开打前看 5 分钟**：读页头一句话 → 扫速记区核心牌与硬限制 → 看单轨时间轴建立整场冷却节奏。
2. **打本时瞄第二屏**：用吸顶阶段导航或高频职责清单直跳当前波次，扫带「必做」标签的高亮行确认动作。

## 一、端到端制作流水线（工具链）

从零做一本新 DPS 副本攻略，按固定 6 步走，**不要手工复制旧副本目录**（避免带入旧版 7 板块、Google Fonts、`.mk.start` 等历史残留）：

1. **采集 5 场证据包**（详见 `guides/tools/README.md`）：
   ```sh
   python3 guides/tools/evidence.py --class guides/tools/classes/<专精>.json \
     --out guides/<职业目录>/sources/<副本拼音>-v2/evidence "<WCL链接#fight=N>@玩家" ×5
   ```
2. **生成标准骨架**（复制定版样板 CSS、裸 `<body>`、空值保护 JS 与标准 `build.py`）：
   ```sh
   python3 guides/tools/scaffold.py --class <职业目录> --slug <副本拼音> --dungeon <副本中文名> --en "<English Name>"
   ```
3. **编码并回解核对天赋**（默认自动选多数派天赋、识别 `specId`、0 差异校验，并输出英雄天赋树与全部差异天赋的国服正式中文名，**严禁根据英文名自行意译**）：
   ```sh
   python3 guides/tools/enc.py --in guides/<职业目录>/sources/<副本拼音>-v2/evidence/talents.json \
     --out guides/<职业目录>/sources/<副本拼音>-v2/tstring.json
   ```
   > 若 5 场均无 WCL 天赋记录（退出码 2），删除 `body.part` 中的 `.code-row` 导入栏并在 `NOTES.md` 说明即可。大版本天赋树更新时跑 `python3 guides/tools/enc.py --refresh-tree`。
4. **阅读证据包 + 定向补查**：先通读 `compare.md`（直击/跳伤已拆分，含血量%）、`interrupts.md`（本玩家与全队打断/驱散 + 读条/可断引导/瞬发形态）、`debuffs.md`（本玩家减益 + 全队敌方减益含职责 + 敌方关键增益）、`team.md`、`segments.md`（含首领相对开打时间）、`spells.md`（含核心技能 5 场实测最短间隔 + Wowhead 冷却与改写）以及 `uses.md`（含后 4 秒窗口承伤/零伤与保人队友 -3/+4 秒承伤；体量较大时可用小脚本按技能/波次检索）。补查时**优先查本地 `evidence/raw/*.json`**（0 API 开销，已含 `team_taken`、`team_interrupts`、`team_debuffs`、`enemy_buffs` 与敌方读条），只有需要本地未采的**队友增益（`team_buffs`）**等字段时再调 `wcl.py events`（控制在十来次内，每次必带 `--ability` 与 `--from/--to`）。
5. **写作与构建**（`build.py` 自动通过 `guides/tools/icons.py` 的 `inject_icons` 解析 `{{I:技能ID}}`、拉取缺失图标并外链到 `guides/icons/`，无需再维护各目录 `icons.json`）：
   ```sh
   python3 guides/<职业目录>/sources/<副本拼音>-v2/build.py
   ```
6. **双门禁验收**：
   - **机器门禁**（必须 0 error）：
     ```sh
     python3 guides/tools/check.py guides/<职业目录>/<YYYY-MM-DD>-<副本中文名>-<职业>.html \
       --source-dir guides/<职业目录>/sources/<副本拼音>-v2 --published
     ```
   - **6 问实战逻辑自检**（见第四节，逐条对照证据核对通过后再交付）。

## 二、页面五块结构与写法细则

页面从上到下固定 5 块，**不再单设「先学四招」「工具箱」「减益表」「首领独立专题」**，杜绝同一条知识反复复述。

| 顺序 | 板块 | 锚点 | 职责 | 不该放什么 |
| --- | --- | --- | --- | --- |
| 0 | 页头 + 吸顶导航 | — | 2–3 句建立整本主思路；提供各段锚点跳转 | 营销口号、筛选/高亮交互按钮 |
| 00 | 开打前速记 | `#prep` | 3–4 张核心牌定位 + 1 条职业硬限制（有则写）+ 全本高频职责清单（可选） | 展开具体首领机制轴（留给路线） |
| 01 | 单轨时间轴 | `#timeline` | 选 1 场代表录像，直观展示关键大招交在哪些时间点 | 多名玩家并排多轨图、本地分叉 `timeline.py` |
| 02 | 按路线逐段 | `#route` | **唯一的知识正文**：按推进顺序写清「看到什么 → 按什么 → 为什么」 | 样本数、单场统计次数、灰色数据小字 |
| 03 | 天赋与页尾 | `#talent` | 可导入的天赋字符串 + 3–4 个不要动的防御/功能天赋 + 页尾参考录像 | 展开纯输出天赋、在正文提参考玩家名 |

### 各板块要点

1. **页头与吸顶导航**
   - 保留 `<p class="lede">...</p>`（`scripts/build_site.py` 提取为首页摘要），且 `<body>` **严禁加任何属性**（`build_site.py` 字面匹配 `"<body>"` 注入 `← 全部手册`）。
   - 导语与正文冷却口径保持一致（绝不把隔轮才转好的技能写成每轮必开）。
   - 吸顶导航用外层 `.nav .wrap` 预留 `padding-right: 124px` + 内层 `.nav-scroll` 横向滚动；路线段名用 `开场 / ①首领一 / ...`，**不与板块号 `00–03` 撞号**；滚到底部自动高亮「天赋」。

2. **00 开打前速记（`#prep`）**
   - **核心技能（3–4 张卡，`.cores` 自适应列数）**：图标 + 技能名 + 冷却/充能/持续时长（来源写入 `NOTES.md`）+ 1–2 句职责定位。不展开具体首领流程，不夸大清除边界（如部分毒清不掉就写「多数自然毒」）。常规输出循环技和全本只用 1–2 次的纯位移不入选。
   - **职业硬限制（可选，至多 1 条）**：只写最容易误判致死的**机制铁律**（如圣骑士 30 秒自律、潜行者斗篷不挡物理且清不掉仪式毒液/感染）。不要把通用常识硬凑成硬限制；没有真硬限制就省略 `.limit`。
   - **全本高频职责清单（可选）**：按专精职责命名为「全本必断读条」「全本必驱减益」或「全本关键控制」，默认 2–5 张卡（`.kicks` 用 `gap:1px` + `box-shadow` 闭合任意折行），点击直跳路线对应行（`id="k-..."`，中性色 `:target` 高亮）。无 ≥ 2 个集中必处理目标时整块省略 `.kicks-box`。

3. **01 单轨时间轴（`#timeline`）**
   - 必须调用共享 `guides/tools/timeline.py`（注入 `GOLD_TL_CSS` 与 `timeline(...)`），保留共享图例类 `.legend i.pri / .e / .v / .muted / .boss / .trash`（图例文字可按本专精替换为具体技能名，如「圣盾术 / 圣佑术 / 保护·牺牲」），严禁分叉或本地打补丁。
   - **代表场选择原则**：按「必做动作覆盖最多、低样本备选点最少」挑 1 场代表录像，常规 **6–14 点**，单条标签 **≤ 8 字**（若最干净的代表场全为非备选点且仅 5 点，宁可标 5 点也不要硬塞低样本兜底点；短 CD / 无免疫 DPS 允许稀疏取样；同波叠牌合并短标签防挤压）。
   - 颜色按**技能类别**区分：`''` = 主大招（`--gold`），`'e'` = 副手牌 1（`--tl-e`），`'v'` = 副手牌 2（`--tl-v`），`'muted'` = 顺手交牌（灰）。
   - 图注明示「单场实录，展示真实冷却节奏，非每波强制照搬」；时间轴主色点均须在路线有说明，但**不要求与路线必做行一一对应**。

4. **02 按路线逐段（`#route`）**
   - 每张卡片分 **小怪（`.trash`）** / **首领（`.boss`）**，固定三层：
     1. **段头 + 节奏栏**：段头标全本段正文涉及的关键小怪名单或首领编号；节奏栏写清**冷却取舍条件**（如「距下个必留点 ≥ 冷却才交 + 未转好时的备选」），高压段用 `.rhythm.warn`（标签写「高压段」，不用「全场最高压」）。
     2. **机制行**：默认三列 `看到什么 → 按什么 → 为什么`；路线副标题写「带「必做」标签的高亮行」，**不写死颜色词**。
        - **必做行（`.row.must`）**：**全页合计**默认 3–6 行（每行至多 1 个 `.btn-chip.pri` 主按钮），按实际复杂度增减。
        - **复杂首领机制**：直接并入该首领卡片，用时间步骤行（`.row.step`，明确每步起算点：读条开始 / 生效 / 减益倒计时）讲清一轮流程；仅当跨场稳定的对比数字能直接说明「为什么这样按」时附 1 组对比条（单场数据不进对比条，直击与跳伤必须分开算）。
        - **「`0 · 免疫`」对比条裁决规则**：允许在对比条里放 `0 · 免疫` 这一行，但**必须同时满足两条件**：① 游戏机制明确对该技能免疫（仅清后续 DoT 如保护清流血只写正文，不画 `0 · 免疫`）；② 在 ≥ 3 场录像中有实测免疫事件，或机制已确证且有实测日志佐证（`NOTES.md` 写明依据）；仅 1–2 场单场观察不画进对比条。
        - **跨段重复小怪**：首次写全，后段简写「同前段」并只补新叠加互动。
     3. **段尾栏**：左侧写建议节奏与未转好备选（只写建议，不写单场统计），右侧放下一段跳转锚点。
   - **信息守恒**：删掉工具箱与减益表后，所有独有细节（驱散类型、应急副解、结束炸裂/爆小怪、吸收盾、物理不吃免疫、精确按键时机）必须全部并入对应路线行。

5. **03 天赋与页尾（`#talent` + `footer`）**
   - 展示 `enc.py` 核对通过的导入字符串 + 复制按钮（省略导入栏时 `build.py` 的 `if '{{TALENT}}' in s:` 与前端 `if(btn&&code)` 自动降级）。
   - 只列 **3–4 个不要动的防御/功能天赋**，常见替换用一句话交代。
   - 5 场参考录像链接只放 `<footer>`。

## 三、内容、取证与视觉硬规则

### 1. 内容与分层取证
- **写攻略，不写统计报告**：正文禁出现参考玩家名，禁写 `5/5`、`五场`、`中位数`、`平均`、`共 N 次`、`一场按 X 次`、`全场最多/最重`。
- **数字准入**：只用在两处——① 技能精确窗口（冷却、充能、持续、读条秒数、码数，须记入 `NOTES.md`）；② 直接解释「为什么这样按」的跨场幅度或对比条。
- **三层取证门槛**：
  1. **机制事实**（伤害属性、读条、驱散、免疫判定）：以 `spells.md` + `compare.md` / `debuffs.md` 为准，绝不望文生义。
  2. **常规推荐打法**：多数样本一致（≥ 3/5）且有窗口内外承伤或移除对比；仅 1–2 人做的常规打法直接删，记入 `NOTES.md`，不进正文推荐或对比条。
  3. **应急兜底 / 备选打法**：允许低样本或由机制事实支撑，但正文必须明标「兜底 / 备选」，不得写成常规主轴或画进主轴时间轴。
- **保人型 DPS 的定向补查**（`evidence.py` 已采集本地 `team_taken`、`team_interrupts`、`team_debuffs`、`enemy_buffs`，仅不采集**队友身上的增益 `team_buffs`**；`wcl.py events` 支持显式 `--source`）：
  ```sh
  # 1) 查本玩家给队友挂上的保人增益（如保护/牺牲/自由）
  python3 guides/tools/wcl.py events "<WCL链接#fight=N>" --type buffs --source "<本玩家>" --target "<队友>" --ability <保人增益ID> --from m:ss --to m:ss
  # 2) 对照该窗口内队友承伤（验证减伤/免疫/清流血是否生效）
  python3 guides/tools/wcl.py events "<WCL链接#fight=N>" --type damage-taken --player "<队友>" --ability <敌方技能ID> --from m:ss --to m:ss
  ```

### 2. 视觉与变量纪律
- **路线内主强调色只说一件事**：`#route` 内 `--gold` **严格只用于必做行 5 个选择器**（`.row.must`、`.badge-must`、`.row.must .to`、`.row.step.must .when`、`.row.must .btn-chip.pri`）。普通首领节点、节奏标签、跳转链接、`:target`、对比条全部用中性色；禁用旧版彩色药丸（`.pill` / `.tag.magic` 等）。
- **`:root` 外零硬编码色值**：`head.part` 与 `body.part` 除 `:root`（29 个完整变量）与对比条柱宽 `style="width:..."` 外，不得出现任何硬编码色值或 rgba。共享 `timeline.py` 仅保留旧页回退兜底。
- **纯系统字体 + WCAG AA**：禁止 Google Fonts 或外部 CSS/JS CDN；全部可读文本与按钮反色对比度 ≥ 4.5:1（`check.py` 自动核验）。

### 3. 三类 DPS 适配矩阵

| DPS 类型 | 速记 3–4 格怎么选 | 顶部高频职责清单（可选） | 时间轴怎么画 | 路线正文重点与动作写法 |
| --- | --- | --- | --- | --- |
| **免疫 / 硬解型**<br>（潜行者、法师、猎人等） | 免疫/硬解 → 常驻减伤 → 副减伤 → 自疗/位移 | **全本必断读条**（短打断且 ≥ 2 个关键读条时保留） | 标 1.5–3 分钟免疫与核心减伤点（6–14 点） | 写清免疫能/不能挡什么、顺手交牌的冷却余量与未转好备选 |
| **短 CD / 无免疫型**<br>（武器战、噬灭 DH 等） | 主减伤 → 副减伤/吸血 → 群控/打断 → 关键位移 | **全本必断读条**或**关键群控点** | 允许稀疏取样，只标高压覆盖窗口或 1.5 分钟以上大减伤 | 区分「单波致死需叠减伤」与「连波持续伤需错峰」；远程标明射程、站位与打断分工 |
| **保人 / 驱散辅助型**<br>（惩戒骑、鸟德、暗牧等） | 保人/免疫牌 → 常驻减伤 → 驱散 → 救急回血 | 按需选**全本必断读条**或**全本必驱减益** | 标免疫、大保人牌与关键减伤轴（6–14 点） | 给队友交牌用 **`[技能] <span class="tgt">给目标</span>`**（如 `[保护祝福] 给流血队友`，避开与第 2 列 `→` 双箭头）；非目标文字用 `.act-note` |

### 4. 新 DPS 专精接入 4 步清单
引入仓库尚未覆盖的新 DPS 专精（如冰法、狂暴战、增强萨等）时，按序完成 4 件事：
1. **写采集配置**：参照 `guides/tools/classes/rogue.json` 新建 `guides/tools/classes/<专精>.json`（`defensives` 写施法 ID、增益 ID、兜底持续秒数；`always` 写打断、群控、保人、关键位移 ID）。
2. **定 `:root` 配色**：已有标准 v2 的职业直接用 `scaffold.py` 内置色板（`rogue` 金 `#f2d24b`、`paladin-ret` 沿用 `duya-v2`/`mimou-v2` 圣骑士粉 `#f39cc3` 而非 `zhuwang-v2` 旧金色试验稿、`demonhunter-devourer` 紫 `#c77ae6`、`warrior-arms` 褐金 `#d8ad7e`）；新专精按职业色在 `head.part` 调出暗底 ≥ 4.5:1 的 `--gold`、`--gold-dim`、`--on-gold`，用 `check.py` 验对比度。
3. **注册发布入口**：把新目录登记进 `scripts/build_site.py` 的 `CLASSES`，并在 `site/img/icons/<icon>.jpg` 放好专精图标；成品文件名必须为 `guides/<职业目录>/YYYY-MM-DD-<副本中文名>-<职业>.html`（第 4 段起命中 `DUNGEON_INFO`）。
4. **验证天赋编码**：运行 `python3 guides/tools/enc.py --list-specs` 确认 `specId` 在节点树内（缺或过旧时跑 `--refresh-tree`），再用 `enc.py` 编码回解。

## 四、交付前双门禁（机器校验 + 6 问实战逻辑自检）

### 门禁 A：自动化脚本（必须 0 error）
```sh
python3 guides/tools/check.py <成品HTML> --source-dir <源码目录> [--published]
```

### 门禁 B：6 问实战逻辑自检（`check.py` 扫不出，写完逐条对照证据回答）
1. **冷却算术 & 多段机制总耗时**：
   - 凡写到「顺手交」「两拨各交一次」「隔轮交」的地方，是否都写了明确的**间隔条件（≥ 冷却）与未转好时的备选**？
   - 凡用免疫/短减伤应对**多段机制**（读条 + 后续延迟爆炸/分摊），是否核对过**总耗时 vs 技能持续秒数**（例如 4.5 秒读条 + 5 秒后续惊雷 = 9.5 秒 > 8 秒圣盾，必须写清延后开启时机）？
2. **时间起算点**：
   - 复杂首领步骤是否把「开始读条 / 技能生效 / 减益倒计时」彻底拆清？冷却推算是否核对过 `segments.md` 里的首领战相对开打时间（`+Xs`）？
3. **样本纯净度 & 直击/跳伤拆分 & 窗口内命中确认**：
